# ADR-0001：以 CLI Agent 为底层承载 Skill

- 状态：已接受
- 日期：2026-11-08

## 背景

Athena 当前通过 `AgentSession` 适配本机 Codex、Claude Code、Gemini CLI、Pi 和 Cursor Agent。Skill 需要在多个 Agent 之间提供统一的发现、选择、记录和注入能力，同时保留各 CLI 自身的沙箱、工具和审批边界。

Skill 与 MCP 的职责不同：Skill 提供任务指导和资源上下文，MCP 提供外部工具或资源连接。本阶段需要先完成 Skill 基础闭环，不把 MCP 配置和调用混入 Skill 模型。

## 决策

1. Skill 采用 Agent Skills 兼容的目录结构，以 `SKILL.md` 为入口。
2. 首期只发现工作区 `.agents/skills`，不自动扫描用户级目录或其他 CLI 专属目录。
3. Athena 在任务级提供 Skill 多选，由用户主动选择当前任务使用的 Skill。
4. 每次发送前重新扫描和校验 Skill；当前运行中的任务不热更新。
5. 采用渐进式读取：向 Agent 提供 Skill 元数据和受控目录上下文，由底层 CLI 按需读取 `SKILL.md` 及资源。
6. 单轮最多选择 3 个 Skill，单个 `SKILL.md` 不超过 12KB。解析失败的 Skill 与其他 Skill 隔离。
7. 记录 Skill 名称、来源、内容哈希和注入状态，不重复保存完整正文。
8. Skill 不绕过底层 CLI 的原生沙箱、工具限制或审批策略；脚本是否执行由 CLI 原生能力决定。

## 备选方案

### 直接调用各家模型 API

不采用。当前会话、登录、模型选择和权限边界已经建立在本机 CLI 适配层之上，切换 API 会同时引入新的认证、用量、协议和安全边界。

### 让每个 CLI 自行发现 Skill

不采用。不同 CLI 的目录约定和能力支持不一致，Athena 将无法统一展示选择结果、记录来源和处理能力降级。

### 首期同时实现 MCP

不采用。MCP 有独立的服务器配置、进程生命周期、工具授权和结果验证问题；与 Skill 同期实现会扩大首期边界并模糊领域模型。

### 把完整 Skill 正文复制到提示词

不采用。完整正文会增加上下文体积，且会话记录容易膨胀。渐进式读取保留 Skill 目录的原始结构和资源访问能力。

## 补充决策：Skill 与 Athena MCP Endpoint

基于对 T3 Code 产品模型的参考，本项目将首期范围扩展为 Skill 与 Athena MCP Endpoint 的协同能力，但不照搬未验证的远程实现细节：

1. Athena 提供本机 MCP Endpoint，外部 Agent 可通过 HTTP 访问受控的状态、线程和配置能力；远程安全传输作为兼容边界预留，不把明文局域网地址视为完成远程授权。
2. 首期采用本机用户显式批准连接，不实现 OAuth、配对码、远程浏览器审批或 30 天远程授权。
3. 外部 Agent 映射到现有 Conversation/AgentSession，支持读取项目、线程、Provider、模型等状态，以及启动、发送消息和停止线程。忙碌线程收到的新消息进入后续轮次，不打断当前轮次。
4. 访问模式分为只读、监督式和完全访问。外部 Agent 可以在完全配置权限下修改 Skill、MCP、Agent 和工作区配置；该配置权限不等同于绕过浏览器、桌面或其他敏感动作的本机审批边界。
5. 本机任务界面和外部线程参数分别显式选择 Skill 与 MCP。Skill 不隐式启用 MCP，MCP 也不反向修改 Skill 选择。
6. 本阶段借鉴 T3 Code 的本地 Agent 控制台、项目、线程和外部 Agent 产品模型；不把页面中未展示源码的实现细节、通用 MCP 工具清单或远程服务生命周期当作已验证事实。

## 后果

正面影响：

- 复用现有 AgentSession 和 CLI 登录能力。
- 用户可在任务层明确控制 Skill 使用范围。
- Skill 版本变化不会污染已运行任务。
- 历史记录可以追溯使用过的 Skill 版本。

代价与限制：

- 各 CLI 对目录读取、脚本执行和路径访问的支持可能不同，需要显示能力降级。
- Athena 需要为 Skill 目录建立安全的路径校验和大小限制。
- MCP 需要后续单独建模，不能直接假定 Skill 的目录模型可复用。
