# 浏览器交互性能修复

日期：2026-10-31。基线为 `2d11abe`，修复版本为 0.3.2。

## 原因和改动

- 手动滚动原先仍走空闲帧限速：每帧确认额外等待约 41.7ms，与捕获、编码和传输时间叠加，复现页只有约 15fps。鼠标、滚轮、键盘和样式拖动现在会开启短暂交互窗口，立即确认帧；结束后恢复空闲节奏。
- 120Hz 触控板输入原先逐条串行执行，5 秒滚动之后仍积压约 5 秒。现在合并同一标签、位置、方向和修饰键下尚未执行的滚轮增量，保留总距离。点击、其它命令、方向变化或坐标变化构成合并边界，过期标签输入仍拒绝执行。
- 每个输入包原先会查询 frame 树，即使页面已经处于人工控制状态。现在复用已知状态，仅在需要从 Agent 交还控制权时遍历；新文档的默认来源仍为 human。
- 启动参数原先强制关闭 GPU，宽页面的高分辨率捕获受到软件渲染限制。移除该覆盖，使用 Chromium 的默认加速与回退策略；画面流允许最多三帧在途。空闲 ACK 按时间分散，避免扩大在途数量后增加空闲帧率。

保留 Retina DPR 2、JPEG quality 88、2048px 最大边长和原有页面/图片坐标映射。没有改写选区高亮、网站 CSS 或浏览器工具授权边界。

## 本机实测

同一个 Electron → IPC → BrowserOS → 图片解码链路，自动产生约 120Hz 连续滚动；每段 5 秒。分别测量未选中和选中固定页头后的状态。最终版本在两种页面各跑三轮；宽页面包含 120 个条目。

| 场景                 | 未选中 fps | 已选中 fps | 帧间隔 P95（ms） | 停手后输入完成（ms） |
| -------------------- | ---------: | ---------: | ---------------: | -------------------: |
| 修复前，自适应页面   |  15.2–15.2 |  14.6–14.6 |        75.4–76.6 |        5152.0–5482.0 |
| 0.3.2，自适应页面    |  58.6–59.1 |  58.9–59.2 |        18.9–19.6 |            42.0–46.0 |
| 0.3.2，1100px 宽页面 |  56.3–56.6 |  55.5–56.7 |        28.2–32.9 |            41.0–72.0 |

打包后的 0.3.2 另测了宽页面中的普通文档流选区（选中元素会随滚动离开视口）：未选中 48.1fps、已选中 55.8fps，帧间隔 P95 为 30.4/32.2ms，停手后输入完成为 54/59ms。

`presentedFps` 统计嵌入图片已完成 decode、仍对应当前图片且内容变化的帧；不是外层 React 页面或原生网页的 requestAnimationFrame 频率。输入完成时间包含队列屏障与后续两次原生渲染帧。基线在修复前隔离构建中测量，旧队列的排空按实际滚动位置确认。不同网页内容、屏幕和机器负载会影响数值。

性能用例断言滚动帧率、帧间隔、输入排空时间和滚动距离。队列用例覆盖连续增量、点击边界、反向/横向/修饰键变化、失效标签、无效数据、来源切换及空闲 ACK 释放。

另运行真实 BrowserOS 的浏览器套件、页面缩放、选区反馈、编辑器布局和延迟解码旧帧隔离用例。首次全量运行中跨域 iframe 用例曾偶发失败；原版及修复版单独运行通过，修复版定向连续 10 次通过。随后完整浏览器回归 26 项全部通过，单元套件 123 项通过、11 项按环境跳过；缩放、选区、布局和延迟解码用例全部通过。此现象没有被当作滚动根因，也没有据此加入固定延时或绕过命中检查。

本次未改动运行中的既有用户配置与网页。修复包单独生成，源码推送和发布属于后续操作。

## 2026-11-20 · Agent 改页与生成代码时的输入响应

固定任务在本机修改网页标题和背景色。测试夹具批准本地脚本，由真实 agent-browser 和 Chrome 执行并读回结果。改前四次工具回执耗时中位数为 1,669 ms，改后为 143 ms。此前脚本已完成，宿主仍在等光标演示结束。现在结果可以先返回，下一次 Agent 访问网页前会释放剩余的演示。滚动中的用户接管、停止任务和进入共享仍有独立边界。演示进行中复用人工交互的短时高频捕获。四轮可见动画期间，宿主捕获帧率中位数从 24.4 fps 升至 51.7 fps。

另用隔离 Electron 窗口回放相同的 96 段代码输出，保留 16 条既有 Markdown 回答。每轮在右侧网页连续点击 6 次，并由本机测试网站确认收到。分别构建启用、关闭两项渲染优化的版本，每个版本跑三轮。旧版每轮收到 9–12 帧，却额外重设位图 46–47 次；新版本每次收到的帧只赋值一次。历史回答复用已渲染的 Markdown。外层渲染器动画帧间隔的 P95（三轮中位数）由 43.3 ms 降至 10.2 ms，18 次点击从发出到网站确认的中位数从 35.5 ms 降至 15.5 ms。结果会随机器负载变化；本组没有向远端模型发请求。

## 2026-11-21 · 已选标题与副标题的布局

09:21 的实际 Codex 请求使用 `gpt-6.1-sol / low`。Athena 接收请求约 20 ms 后已有网页任务，约 62 ms 后原生任务开始。Codex 预热超时，随后四次 Responses WebSocket 连接分别在发送后约 23、38、54、70 秒超时。用户在 70.646 秒时停止；此前没有公开助手正文、工具调用或网页写入。旧界面把等待和重连合并显示为“思考中”。

本机使用 macOS 系统代理。旧进程没有代理环境变量，内置 OpenAI Provider 走直连时，向同一官方端点发起的独立网络探测 6 秒 TCP 超时。新的 Codex 会话在适用时使用其原生系统代理开关，保留显式网络选择与自定义 Provider。用现有 ChatGPT 登录在空的临时工作目录做同条件原生预热，旧设置的 18 秒观察窗口内未完成升级，新设置在开始连线后约 1.37 秒得到 HTTP 101；没有发起模型推理。预热衡量连通性，远端模型首字延迟仍取决于该次服务情况。

在网页上明确要求把已选标题与紧邻的副标题、或两个已选相邻元素横排/纵排时，宿主可直接在当前文档试排。它核对实际几何与裁切，成功才报告，并保留一个可撤销的预览。有既存规则、其他任务约束或不明确的目标时继续交给当前 Agent；停止、人工接管、失效引用与未知写入仍按原网页协议处理。网页打开后可读取运行中的 DOM、布局和样式；将改动保存到项目源文件依然需要源码工作流。

同一示例页、同一标题的隔离 Chrome 对照中，选区快照从 8,857 B 降至 4,891 B，首个引用预检和发送前检查的总耗时中位数从 6.24 ms 降至 2.59 ms。新的快照还包含相邻元素和父级布局。独立 Electron 回归在模型不返回首个 token 的条件下验证了发送、左右位置、撤销以及无法确定布局时的回退。

## 2026-11-21：Agent 操作时的帧率与元素修改的往返

**帧率。** 空闲时帧确认按 24 fps 节流，只有用户输入和 Agent 光标动画的心跳会临时解除。Agent 通过网页执行器点击、输入、滚动，以及页面预览写入，都不在其中，所以它自己引起的画面变化按空闲节奏显示。现在这些动作在执行期间持有帧租约，结束后再保持 700 ms；光标心跳的窗口由 300 ms 延长到 500 ms，避免宿主短暂繁忙时掉回空闲节奏。真实 Chrome 中，对一个持续动画的页面计数 2 秒：空闲 48 帧，Agent 动作期间 122 帧（`tests/browser-direct-edit.test.ts`）。

**宿主停顿。** 任务流式输出的每个间隙都会把全部对话序列化写盘，实际数据文件约 3.1 MB。现在使用紧凑格式，两次写盘至少间隔 2.5 秒；主动保存与退出时的保存不变。这一项依据代码判断，没有单独计时。

**元素修改。** 每轮注入的页面摘要没有元素引用，而 `workbench_browser_edit` 只接受引用，模型必须先调用一次 `workbench_browser_query`，这是一次完整的模型往返。现在 `edit` 与 `inspect` 可以直接用 `selector` 指定元素，可加 `containing` 或 `nth`；宿主在当前页面实时定位，恰好一个命中才执行，多个命中时返回各自的引用且不改动页面。页面摘要改为加载完成后预读：发送时刷新，200 ms 内没有读回就使用预读结果并标明读取时间。各 CLI 的说明已改为目标明确时一次调用完成。用户点击、输入或导航后仍需重新读取，这条边界没有改变。

未处理：帧仍以 base64 字符串经宿主主线程转发；模型截图与录屏共用同一个页面会话。
