# Athena 首次引导 · 与 Athena 的第一次合作

[设计分区](https://www.figma.com/design/vEL0JeDlefvuvLjUQQh5SB?node-id=126-3379) · [初次见面](https://www.figma.com/design/vEL0JeDlefvuvLjUQQh5SB?node-id=128-5452) · [动效规格](https://www.figma.com/design/vEL0JeDlefvuvLjUQQh5SB?node-id=135-4727)

2026-11-02。本轮在现有「01 · 桌面界面与原型」页面新增首次引导 Section。交付为设计和原型，不修改应用源码、执行安装、改变登录或申请系统权限。

## 已确认方向

- Athena 主动打招呼，用户通过点击回应。准备工作被组织为连续对话。
- 开场头像与「你好，我是 Athena。」同一行，减少垂直高度。1600 × 1000 主稿中，头像 56px、标题沿用 Athena Display 36/48；900 × 760 窄窗口仍保持横向组合。
- 当前消息、动作与状态优先；上一条用户选择收成右上回复。按钮的变形与移动说明「这就是你的回答」。
- 完成后保留人物锚点，展开侧栏和输入区，进入现有工作台。首次进入不填充虚构历史对话。
- 动画是本轮核心交付：六段原生时间轴，不仅是静态箭头或动画描述。

## 流程与完成条件

1. **认识**：首次问候；可查看能力介绍。开场由本地确定流程驱动，不依赖模型连通。
2. **检测**：查找 CLI、读取版本与登录状态。已安装且登录可确认时跳过安装和登录；未确认不是成功。
3. **安装**：显示官方来源、安装计划、实际目的地与环境变更 → 用户点击下载并安装 → 环境检查、下载、完整性校验、安装、启动验证。没有已知总量时使用阶段标签，不编造百分比。取消和失败后重新检查现状，不能把部分写入当成完成。
4. **登录**：由系统浏览器承接官方流程；Athena 等待并允许重新打开、取消或核对。回调到达后重新读取账号与连接状态。点击「我已完成」只要求核对，不作为成功证据；本次取消不退出其他客户端已有登录。
5. **工作目录**：系统选择器返回真实目录 → 用户确认 → 检查可访问性。取消不覆盖旧目录。目录选择不等于所有命令或任意文件的永久授权。
6. **权限**：只为真实操作提出具体范围。系统需要授权时交给 macOS 原生提示；没有系统提示则直接按检查结果继续。拒绝、撤销、目录移动或不可写，提供重选、重试或稍后设置。应用内审批与系统授权分开。
7. **网页工具（可选）**：发现现有 BrowserOS neo，缺少时显示来源和真实下载信息后准备运行组件。准备失败或跳过不阻挡已就绪的项目任务。首次使用网页功能时可再进入准备。
8. **进入工作台**：必须由实际就绪状态决定可执行能力。完成全部准备与「网页稍后」使用不同的退出画板，避免转场短暂把浏览器显示为已就绪。

「稍后设置」进入带继续准备入口的工作台，未满足条件时任务发送不可用。已配置的老用户不强制重复引导。中断后保存已经确认的事实，重新打开时复查；不恢复未决授权为成功，不自动重放写操作。

### 等待、中断与可访问性

- 不为动画强制延迟真实结果，不通过最短等待或倒计时伪装系统工作。
- 同一步重复点击不重复安装、登录或发起权限请求；取消后过期回调不能覆盖新的选择。
- 新状态到达时取消旧动效，从当前视觉值衔接。系统选择器和登录页出现后不重复抢前台。
- 有实际待执行工作才显示持续等待动效；失焦或后台暂停非必要动画。
- 减少动态效果时移除位移、缩放与循环，用 0–80ms 状态切换。Figma 附有静态开场示例；全流程键盘、读屏和 reduced-motion 行为仍需运行时实现与验收。
- 引导主按钮44px；焦点顺序跟随阅读顺序，切换后聚焦标题或下一操作。等待使用礼貌播报，错误保留具体原因与恢复动作。

## 实现接缝与边界

| 已存在，可复用 | 需要新增或验证 |
| --- | --- |
| `detectAgents`、`agents:refresh`、CLI 版本与登录探测 | 安装计划、官方分发获取、完整性校验、取消与恢复 |
| `CodexSession` 初始化、预热和连接复用 | 由当前 CLI 版本支持的登录发起、取消、回调与状态桥接 |
| `settings:workspace` 系统目录选择 | 可访问性检查、目录失效状态与按需系统授权交接 |
| 当前审批请求与停止操作 | 首次引导进度持久化、状态机、过期事件屏障 |
| BrowserOS neo 发现、配置、运行状态 | 可选准备入口、真实进度、失败恢复与动效状态映射 |

保留 `app.agent.workbench`、`Agent Workbench` 数据目录、`WORKBENCH_*` 和内部工具/IPC 兼容标识。登录凭据仍由 Codex 管理，不把密码、密钥或登录 URL 存入引导进度。文件夹只是默认工作目录，不应被文案当作已经验证的安全沙箱。

已有网页功能不等于原生桌面 Computer Use。首次引导不预先要求屏幕录制、辅助功能、全盘访问或飞书配对。后续新增这些能力时，再按实际范围设计授权。

当前 app-server 集成是本地工作台语境。若未来进行商业或托管分发，需重新核对官方认证适用范围，不能直接继承本地集成假设。

## 官方依据

- [Codex CLI 安装](https://learn.chatgpt.com/docs/codex/cli#getting-started)：macOS/Linux 独立安装器，以及 npm/Homebrew 备选。设计不把 Node.js 设为所有用户必经前置项；具体安装路径与环境变更要由真实安装计划提供。
- [Codex login](https://learn.chatgpt.com/docs/developer-commands#codex-login)：官方浏览器登录与登录状态查询。存在凭据不保证后续模型请求一定可用。
- [Codex App Server](https://learn.chatgpt.com/docs/app-server#auth-endpoints)：账号读取、登录发起/完成/取消，以及当前认证适用范围。接入需按安装版本协商并验证。

## 原型与验证边界

所有应用界面由可编辑文字、组件实例、布局和品牌图片构成，没有整屏图片覆盖。原型中的定时跳转只是示例检查回调，不运行系统安装、授权或浏览器任务；重新打开登录页等外部动作在交接中标识，未伪装成可执行系统行为。
