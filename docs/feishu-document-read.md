# 飞书文档读取

在 Athena 桌面输入框或已配对的飞书单聊发送 HTTPS 文档链接，例如“总结这份文档：链接”。宿主先识别资源、读取正文，再交给当前对话的 Agent；富文本链接保留真实 href，显示名称不能替代地址。一次最多处理 5 个链接，相同完整地址去重。

读取使用本机 `lark-cli --as user`，需要用户自行安装并完成文档访问授权。Athena 不读取 CLI 内部凭据，也不以机器人身份或浏览器登录页代替正文。子进程只取得运行所需的基础环境，不继承模型服务密钥与 Node 注入选项。

- Docx 和 Wiki：解析底层对象后取 Markdown 正文；保留来源 query/fragment，`#share-` 选区锚点传给底层读取。
- 旧版 Doc：通过 Markdown 导出读取。
- 上传文件：仅读取已有可下载文本预览。
- 表格、幻灯片、多维表格、图片或无文本预览的文件：明确提示不支持，不冒充已读正文。

内嵌资源不会自动递归展开。单份正文最多 160 KB；发送给 Agent 的文档上下文最多 50,000 字符，超限需改用章节链接或分批发送，不静默截断。正文及其引用作为不可信参考资料，不能扩大任务授权或改成宿主指令。

正文成功后保留 URL、标题、资源类型、可获取的版本与 SHA-256 摘要。导出临时目录在成功、失败或停止后清理；读取失败结束本轮，不发送缺失正文的模型任务。停止或退出会中止读取，旧任务的晚到结果不能继续执行。

直接发送链接的读取由宿主完成，沿用当前所选 CLI，不依赖该 CLI 的浏览器工具。动态 `workbench_feishu_read` 工具沿用当前宿主工具适配范围；本分支基线只有 Codex，其他 CLI 的动态工具连接由独立浏览器适配 PR 提供。

模型可能引用或复述正文，完整任务内容也会交给当前配置的模型服务；聊天和工具输出沿用普通本机存储规则，不属于飞书凭据的加密范围。

验证入口：

```bash
npx tsx --test tests/feishu-documents.test.ts tests/feishu.test.ts
npm run build
# 真实 Electron、替身 CLI 和文档，无模型请求或飞书访问：
npx tsx tests/feishu-documents.e2e.ts
# 真实只读，执行前须确认具体文档；不发消息、不调用模型：
WORKBENCH_FEISHU_READ_ACCEPTANCE=1 npx tsx tests/feishu-documents.live.ts '已确认的文档链接'
```

隔离验证不代表真实用户授权、外部消息触发、模型总结和飞书回传闭环已完成。
