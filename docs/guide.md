# 带做：Athena 指，你来做

有些事不该由 Agent 代劳：你想学会的流程、登录、付款、最后一次确认。带做时，Athena 在页面上一步一步指出该看哪里、点哪里、填什么，每一次点击和输入都是你自己的。

## 使用

1. 在对话里直接说，例如「教我怎么在这个后台开通企业邮箱」「带我走一遍报销流程，我自己来点」。Agent 也会在轮到只能由你完成的步骤时主动带做。
2. 浏览器会自动显示出来。页面上当前这一步的目标被高亮，旁边是一张说明卡：这一步做什么，以及进度。
3. 照着做：
   - 要你点击的步骤，点一下高亮处就进入下一步；
   - 要你填写的步骤，填好后点「下一步」，或在离开输入框时自动进入下一步；
   - 只是讲解的步骤，看完点「下一步」。
4. 说明卡上还有四个按钮：
   - **结束**：到此为止。Agent 不会重新开始，也不会替你做完剩下的步骤；
   - **上一步**：回到前一步；
   - **交给 Athena**：剩下的步骤由 Agent 接着完成；
   - **跳过**：这一步不做，直接看下一步。
5. 对话里同时有一张步骤清单，标出做到了第几步。点「去页面操作」回到页面，点「结束带做」等同于页面上的「结束」。

流程跨页面时不用重新开始：你点击后页面跳转，说明会出现在新页面上；切换标签页，它也跟着你。

## Agent 能知道什么

带做结束后，Agent 收到的是每一步的结果：做了、跳过了还是没做到；是点击目标通过的，还是用卡片上的按钮通过的；要填写的输入框最后是否有内容。**你填写的内容本身不会被读取，也不会返回给 Agent。** 之后 Agent 必须重新读取页面才能继续操作，页面上发生过什么以它重新读到的为准。

带做期间 Agent 不操作页面，你在页面上的点击和输入也不会中断这轮任务。

## 边界

- 一次最多 12 步，每步说明不超过 280 个字符。
- 第一步的目标在页面上找不到时，带做不会开始，页面上什么也不显示，Agent 需要先确认元素再重试。后面的步骤找不到目标时，说明仍然显示并注明还没找到位置，目标出现后自动高亮，你也可以跳过。
- 只在页面主体上指示，不进入内嵌的子页面（iframe）。按文字找目标时，不会用输入框里已填的内容或受保护的内容去匹配。
- 15 分钟内没有走完会自动结束，Agent 会说明停在哪一步，不会自行重来。
- 停止任务会同时结束带做；浏览器停止运行时也会。
- 共享期间页面由参与者操作，不能带做，需先停止共享。
- 只读对话里也可以带做，这时没有「交给 Athena」，因为 Agent 在这类对话里不能操作页面。
- 从飞书发起的任务需要带做时，飞书里会提醒一次，请回到 Mac 上的 Athena 跟着页面操作。
- 说明文字由模型撰写，可能不准确；涉及付款、删除等操作时，请以页面上实际显示的内容为准。

## 实现

Agent 调用一次 `workbench_browser_guide`，给出全部步骤。每一步有一句说明（`note`）、用户要做的事（`action`：`look`、`click` 或 `input`），以及目标的位置：CSS 选择器、控件上的可见文字，或当前页面的元素引用。调用一直等到带做结束才返回，结果为 `completed`、`ended_by_user`、`handed_over`、`stopped`、`timed_out` 或 `page_closed` 之一。

- 页面一侧（`src/main/browser-page-guide.ts`）在隔离环境里绘制高亮、光标和说明卡，只认浏览器产生的真实点击与修改事件，脚本合成的事件不算数。说明卡上的点击不会传给页面，也不会夺走页面里的焦点。
- 宿主一侧（`src/main/browser-guide.ts`）决定当前显示哪一步，在页面跳转或切换标签后把这一步重新放到页面上，并忽略旧页面发来的过期报告。
- 任务层（`src/main/web-runtime.ts`）在带做结束后让此前的页面观察全部失效，Agent 在重新读取页面之前不能修改页面。
- 对话里的步骤清单复用等待用户处理的卡片，但没有「允许」这一项：带做只能在页面上完成，或由你结束。

## 验证

- `tests/browser-guide.test.ts`：步骤校验、逐步推进与每步的通过方式、第一步找不到时不开始、后续步骤缺目标时可跳过、页面跳转后重新显示并忽略过期报告、上一步、结束、交给 Athena、只读时不可交接、停止、关闭页面、超时、切换标签。
- `tests/browser-guide-page.test.ts`：在真实页面里核对高亮、光标与说明卡，按可见文字定位且不匹配受保护的内容，找不到时说明原因且不显示，只认真实点击（包括按下时被页面重绘的元素），说明卡上的点击页面收不到也不丢焦点，填写后只报告是否有内容，其他浮层被清除后自行恢复并跟随稍后出现的元素。
- `tests/browser-guide-runtime.test.ts`：真实 Chrome 中跨两个页面的三步流程，点击与输入全部经由用户输入通道；结果里不含输入的内容；讲解步骤不会替用户提交。
- `tests/web-guide.test.ts`：任务层。带做期间用户的操作不打断任务，结束后旧的元素引用被拒绝直到重新读取；只读对话可以带做但不能交接；停止任务后页面上不留任何内容。
- `tests/guide-ui.e2e.ts`：真实应用加模拟的 Codex 协议。步骤清单随用户点击推进，快捷键不会误答这张卡片，「结束带做」、走完和停止任务三种结局在对话里的记录各自正确。

以上均未调用真实模型：模型何时选择带做、步骤写得是否清楚，尚未在真实对话中验证。飞书提醒只在单元测试里核对了内容，没有真实发送。
