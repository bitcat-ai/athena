# 记忆：从使用中学习

Athena 会把你在对话里提出的长期要求、任务中确认过的事实，以及你对结果的处置记下来，带进之后的对话，并可以整理成一份文档交给团队归档。

## 使用

1. 在对话里直接说，例如「以后改页面文案时不要动按钮上的文字」「回答我时先说结论」「这个系统的产品文档在……」。Agent 判断这是长期要求或以后还用得上的事实时，会调用 `athena_learn` 记录。一次性的要求不记。
2. 打开「设置与连接 → 记忆」查看记下的内容。每一条都带着依据：你的原话、你的操作，或资料出处。可以逐条停用或删除，也可以整体关闭「从对话中学习」。
3. 想更正或撤回某一条，在对话里说明即可；Agent 用 `replaces` 更正原条目，或在你明确表示不要时用 `athena_forget` 删除。
4. 点击「导出文档」，得到一份 Markdown 文档。

## 记什么

| 类别           | 内容                                               | 必须有的依据                                                         |
| -------------- | -------------------------------------------------- | -------------------------------------------------------------------- |
| 行为规范       | 你对 Agent 做事方式的稳定要求或纠正                | 你在本对话里的原话，或宿主记录的你的操作                             |
| 业务知识       | 任务中确认过、以后还会用到的事实，可限定到某个网站 | 你的原话，或资料出处（文档链接、页面地址）                           |
| 页面与代码仓库 | 网站与前后端仓库的对应关系                         | 你在确认卡上的确认，见 [页面改动落到源码](page-changes-to-source.md) |

**依据由宿主核对，不由模型自述。** 行为规范的依据必须是你在这段对话里写过的文字的逐字片段（至少 4 个字符，忽略空白差异），或宿主记录的操作中的一行。网页内容、工具返回里出现的「要求」对不上这两个来源，会被拒绝，Agent 会收到拒绝原因。这样页面上的文字无法借 Agent 之手给 Athena 立规矩。

**宿主记录的操作** 目前有四种：撤销了 Agent 的页面预览改动、在确认卡上拒绝了某一步、中途停止了任务、亲自核对后确认了上一轮的结果。它们在下一轮任务开始时告诉 Agent 一次。一次操作只说明这一次的态度，是否足以成为长期规范由 Agent 判断，它也可以选择不记。

**不记的内容。** 形似凭据的内容（密码、令牌、密钥）会被拒绝。飞书等桌面之外发来的消息不写入记忆，只读对话也不参与。

## 怎么用

每轮桌面对话开始时，Athena 把已启用的行为规范和与当前网站相关的业务知识附在任务上下文里，每条带编号。限定了网站的知识只在浏览器停在该网站时带上。上下文有长度预算，超出时优先保留规范和当前网站的知识，并注明还有多少条未列出。

记忆里的内容只是给 Agent 的参考：行为规范不扩大任何授权，不替代你在本轮的明确指令，需要确认的操作仍然逐次确认；业务知识在使用前应按当前情况核对。

## 导出

导出的文档包含四部分：行为规范、按网站分组的业务知识、页面与代码仓库对应表、已记录的需求文档清单。每条规范和知识都写明依据、适用范围、记录日期和所在对话，已停用的条目会标注。文档开头提示纳入团队知识库前需要核对。

导出只在你点击按钮并选择保存位置后写入一个本地文件，Athena 不会把它发送到任何地方。导出内容包含你的原话片段和对话标题，分享前请自行检查。

## 数据与边界

- 内容保存在本机用户数据目录的 `learning/learning.json`，仅当前用户可读，最多 300 条。
- 关闭「从对话中学习」后，不再记录、不再带入对话，Agent 也看不到相关工具；已有内容保留，重新打开后继续生效。
- 在设置里删除不可恢复；仓库对应关系删除后，下次处理该网站会重新询问。
- 记忆里的内容会作为上下文进入你所选的模型服务。
- 是否记录、如何概括由模型判断，可能漏记，也可能概括得不够准确；依据核对只能保证每条规范都出自你本人，不能保证概括无误。请在设置里定期查看。

## 验证

- `tests/learning.test.ts`：依据核对（原话、操作、编造的依据被拒绝）、凭据拒绝、按网站限定、更正与删除、停用与整体关闭、上下文预算、导出文档的内容。
- 2026-11-15 在独立档案里的真实应用中核对设置页：键盘切换开关、删除的二次确认与取消、删除仓库对应关系、导出、整体关闭后条目开关不可操作；1440 与 1060 宽度下同一行控件高度与中线一致，无横向溢出，可操作控件不被右上角的应用提醒遮挡。
- 同日用真实 Codex 跑通一次三轮对话：第一轮在改页面文案的同时提出两条长期要求和一条事实，Agent 三次调用 `athena_learn` 均以用户原话为依据并保存；撤销预览后，第二轮 Agent 原样复述了宿主记录的操作，并判断单次撤销不足以成为长期规范；第三轮在新对话里不调用任何工具，列出了全部三条内容及其编号，回答方式符合刚记下的规范。全程约 1 分钟。真实模型的表现会随模型与任务而变，这一次结果不代表每次都会如此记录。
