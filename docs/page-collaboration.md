# 在同一张页面上协作

Athena 不是一个什么都能代办的通用 Agent。它要改变的是人和 AI 一起做事的方式：两者面对同一张网页，页面本身就是双方交流的语言。人不必把看到的东西翻译成文字，AI 也不必把做过的事翻译成一段总结。

这份文档记录这个方向下已经有的能力，以及接下来可以做什么。

## 已有的三种交流

| 方向             | 含义                                         | 现在的能力                                                                                  |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 你指给 Athena 看 | 用页面上的东西代替描述                       | 选取元素并带入对话；手动调整元素，改动作为预览被记录；手动操作页面时 Agent 的旧观察自动失效 |
| Athena 做给你看  | Agent 的动作发生在你眼前，而不是一段事后报告 | 多枚光标演示每一次修改；整页换风格逐屏画出；预览可逐次撤销；改动可落到真实源码              |
| Athena 指给你做  | Agent 知道怎么做，但由你动手                 | [带做](guide.md)：逐步高亮目标并说明，点击和输入都是你的，Agent 只得知每一步是否完成        |

第三种是这个方向里此前缺少的一环。在它之前，Agent 遇到只能由人完成的步骤只有两个选择：停下来用文字描述该怎么做，或者请求接管。带做让它可以留在页面上，把「怎么做」直接指出来，同时不碰任何属于你的输入。

录制现在也可以作为带做的起点。人演示一次，查看有原始步骤依据的流程草稿，纠正规则，再换一个对象在同站网页上练习。使用方式见[用户指南](user-guide.md#录制与页面共享)。

## 改动时间线

页面上有预览改动时，网页下方出现一行「改动」：每次改动一个标记，最左是原始页面，圆点是你的改动，方点是 Athena 的。拖动滑块或按方向键，页面回到那一步时的样子；拖回最右，全部改动恢复。来回拖动不丢弃任何改动。停在较早的一步再做新改动，之后的改动才作废，并从改动记录里移除。

时间线属于当前这一份页面：刷新或离开后清空，不跨会话保存。页面自己在之后改过同一个元素时，时间线停在能回到的最近一步并说明。被时间线收回的改动不计入「页面改动」，不会落到源码。目前只覆盖页面的主文档，内嵌框架里的改动不在这一行里。

## 内容压测

页面底部状态栏的「压测」把当前页面的文字换成极端情况，看布局哪里撑不住。五种：超长内容（每段三倍长，单个词接上一个很长的姓氏）、清空内容、大数字（数字换成十位数金额）、伪翻译（加重音并加长四成，模拟更长的语言）、从右到左（换成阿拉伯语并翻转页面方向）。替换由页面里的脚本完成，不调用模型，点了立刻生效。

换完之后 Athena 把每个元素和替换前比较，找出新出现的问题：内容被截断、撑出容器、与相邻元素重叠、按钮和导航被挤成多行、清空后塌陷、整页出现横向滚动。有问题的元素在页面上用红框标出，网页下方的一行按问题种类计数，点一下逐个查看；「交给 Athena 修」把清单写进输入框，由你发送。「恢复原样」或选回「原样」把页面还回去。

压测是一次页面预览：它出现在改动时间线上，可以撤销，但不计入「页面改动」，不会落到源码。输入框里已填的内容、隐藏的文字和标了敏感的区域不替换。检查只覆盖上面列出的几种问题，没有发现问题不等于布局在所有内容下都成立；替换的是当前已渲染的文字，页面自己重新渲染后会变回去。目前只覆盖页面主文档，不进入内嵌框架和 Shadow DOM。

## 设计上的共同约束

这几种能力遵守同一组规则，后续的能力也应如此：

- **页面上谁做了什么必须分得清。** 用户的输入经由独立的输入通道，只有浏览器产生的真实事件才算用户的操作；Agent 的动作有光标和记录。
- **Agent 看到的以重新读取为准。** 人动过页面之后，Agent 此前的观察失效，不能凭旧印象继续操作。
- **属于用户的内容不外流。** 带做不读取填写的内容；敏感输入框不进入页面概览。
- **画面上的东西都能收回。** 演示只影响画面，预览可以撤销，带做可以随时结束。

## 接下来可以做的

以下均为设想，**尚未实现**，列在这里是为了说明方向，顺序即建议的先后。

1. **把带做存下来。** 一段走通过的带做保存为可重复使用的流程，下次直接说「再带我走一遍」，或交给同事在共享里使用。步骤已经是结构化的数据，主要工作是保存、命名和在页面变化后提示哪一步对不上。
2. **代为执行已确认流程。** 在当前由人操作的录制带做基础上，进一步支持按用户授权代为执行，遇到规则范围或页面变化时再交还给人。
3. **留在这个网站上。** 对页面的外观调整可以选择「在这个网站上保留」，再次打开时自动套用。现有的整页样式改动是一张附加样式表，适合保存；需要处理页面改版后选择器失效的情况，并明确告诉你哪些规则不再生效。
4. **指着说。** 选中页面上的元素后就地输入一句话，回答或改动也出现在这个元素旁边，而不是回到对话里。对话仍然保留完整记录。
5. **先演后做。** 对不可撤回的操作，Agent 先用光标在页面上演示它打算做的事（点哪里、填什么），你在页面上确认后才真正执行，取代现在对话里的文字确认卡。

暂不考虑的方向：让 Agent 在页面之外代办与当前页面无关的事务。这类能力会把 Athena 变成通用助手，与上面的方向相反。
