# 沙箱实例与回收

沙箱是独立的运行环境，用来运行命令、构建项目和启动预览。它可以运行在两个地方：

| 运行位置 | 是什么                                    | 需要什么                                               |
| -------- | ----------------------------------------- | ------------------------------------------------------ |
| Coder    | 你的 Coder 部署上的一个工作区，按模板创建 | 在「设置 → 沙箱」里连接 Coder；这台 Mac 装有 Coder CLI |
| 本机     | 本机 Docker 里的一个容器                  | 本机已安装并启动 Docker                                |

两种沙箱用同一组工具、出现在同一张列表里，并遵守同一套回收规则。本机沙箱不挂载本机项目、登录凭据或 Docker socket，容器以受限权限运行；Coder 沙箱的权限和网络由所选模板决定。

沙箱有两个来源：

| 来源 | 怎么出现                                                                       | 归属                             |
| ---- | ------------------------------------------------------------------------------ | -------------------------------- |
| 自建 | 你在「设置 → 沙箱」里命名并创建，可以有多个，运行在 Coder 或本机               | 属于你，任何对话都可以点名使用   |
| 对话 | Agent 在任务需要独立环境时自动创建，每个对话按用途最多三个（基础、前端、后端） | 属于那个对话，对话删除时一并回收 |

对话自动创建的沙箱运行在本机 Docker 里。

## 连接 Coder

1. 打开「设置 → 沙箱」（或输入 `/settings sandbox`），在「Coder」一栏填写部署地址和令牌，点击「连接」。令牌在 Coder 的「Settings → Tokens」里创建。
2. 连接成功后显示地址和账号，「运行环境」里出现 `Coder · <模板名>`，每个可用模板一项。

几点说明：

- **地址**须为 HTTPS；本机和内网地址（`localhost`、`10.x`、`172.16–31.x`、`192.168.x`）可以用 HTTP，此时列表里标注「HTTP 未加密」。
- **令牌**用系统钥匙串加密后保存在本机用户数据目录，文件仅当前用户可读。Athena 调用 Coder CLI 时通过环境变量传递令牌，不写进命令行参数，也不读写你自己的 Coder CLI 登录状态和 `~/.ssh/config`。
- **Coder CLI** 需要装在这台 Mac 上（`coder` 命令）。Athena 通过它建立到工作区的 SSH 连接。
- **模板**需要定义 agent，并且工作区里有 Node.js 18 或更高版本。Athena 第一次使用工作区时把一个单文件的守护进程装到工作区的 `~/.athena-sandbox/`，不需要 sudo；模板不满足条件时，创建会以说明原因的错误结束。
- **令牌过期**后列表里提示 Coder 不可用，在同一栏填入新令牌即可，沙箱记录保留。连接期间只能更换同一地址、同一账号的令牌。
- **断开**需要再点一次确认。断开后 Coder 沙箱从列表移除，运行中的会被请求停止；它们的工作区留在 Coder 上，之后在 Coder 里删除。

## 创建和使用

1. 打开「设置 → 沙箱」。
2. 填写名称，选择运行环境，点击「新建」。运行环境是某个 Coder 模板，或本机的三种环境之一：基础 Node、Node 前端、Java 后端。Coder 工作区的创建时间取决于模板；本机环境第一次使用需要先准备镜像，可能要几分钟。
3. 在对话里说出沙箱的名称，例如「在『支付页重构』里把项目跑起来」。Athena 会在这个沙箱里工作；已停止的沙箱在使用时自动启动，文件仍在。
4. 没有点名时，Agent 照常使用对话自己的沙箱。

名称为 1–40 个字符，可用文字、数字、空格和 `. _ -`，不区分大小写且不能重复。自建沙箱最多 20 个。

每个沙箱一行，显示状态、运行环境、来源和回收时间，可以：

- **打开预览**：沙箱里有正在运行的预览服务时，在右侧浏览器打开它。
- **启动 / 停止**：停止只结束进程，文件保留。
- **保留 / 取消保留**：保留的沙箱不会因为长期不用而被删除。
- **删除**：需要再点一次「确认删除文件」，容器或 Coder 工作区连同其中的全部文件一起移除，不能恢复。

当前任务正在使用的沙箱不能手动停止或删除，需等任务结束。

Coder 沙箱与本机沙箱的几处不同：

- **工作目录是工作区的主目录**（`$HOME`），文件路径相对于它；本机沙箱的工作目录是 `/workspace`。停止后是否保留文件取决于模板是否把主目录放在持久卷上。
- **预览**通过一条只监听本机回环地址的 SSH 端口转发打开，沙箱停止时一并关闭。
- **工作区名称**形如 `athena-<本机标识>-<编号>`，在 Coder 的界面里可以看到。

## 回收规则

Athena 运行期间每分钟检查一次，规则在同一页的「回收规则」里调整，对 Coder 沙箱和本机沙箱同样生效：

| 规则           | 默认    | 可选                             | 做什么                                                           |
| -------------- | ------- | -------------------------------- | ---------------------------------------------------------------- |
| 闲置多久后停止 | 30 分钟 | 15 分钟、30 分钟、1 小时、2 小时 | 停止容器或 Coder 工作区，释放资源；文件保留，下次使用自动启动    |
| 多久不用后删除 | 7 天    | 3、7、14、30 天                  | 移除容器或 Coder 工作区和其中的全部文件；标记为保留的沙箱跳过    |
| 同时运行上限   | 4 个    | 2、4、6、8 个                    | 需要启动新的沙箱而名额已满时，先停止最久没用的那个；两种沙箱合计 |

几条边界：

- **正在使用的不动。** 有命令正在执行、当前任务所在的对话正在使用，或它的预览正显示在浏览器当前标签里的沙箱，不会被停止或删除。
- **名额已满且都在使用时拒绝启动。** Athena 不会为了腾位置打断正在进行的工作，而是提示先停止一个或调高上限。一分钟内刚用过的沙箱也不会被挤掉。
- **删除对话时回收它的沙箱。** 只回收 Agent 为这个对话创建的，自建沙箱不受影响。
- **运行位置不回应时不回收它的沙箱。** Docker 没有运行，或 Coder 连不上、令牌失效时，对应的沙箱记录保留，等恢复后再处理；另一边照常回收。
- **回收失败会稍后重试。** 一次停止或删除没有成功时，约十分钟后再试，不会每分钟重复请求。
- **退出 Athena 时停止运行中的沙箱。** 本机容器随应用停止；运行中的 Coder 工作区会被请求停止，文件保留。
- **旧版本留下的沙箱会被列出。** 对应的对话还在的归到该对话名下，对话已删除的标为「对话已删除」，只能删除；两者都按上面的期限回收。

「使用」指 Agent 在沙箱里执行命令、读写文件、启动服务，或你手动启动它。每次使用都重新计时。

需要长期留存的结果不要只放在沙箱里：让 Agent 导出为产物，或把沙箱标记为保留。

## 数据与边界

- 沙箱的记录和回收规则保存在本机用户数据目录的 `sandboxes/instances.json`，仅当前用户可读；本机沙箱里的文件在同一目录下各自的文件夹里，Coder 沙箱的文件在它的工作区里。
- 回收只处理当前用户数据目录创建的沙箱：本机上其他 Docker 容器不会被碰；在 Coder 上，每个用户数据目录有一个随机生成的本机标识，写在工作区名称里，Athena 只列出、停止和删除带这个标识的工作区。你账号下的其他工作区，以及同一账号在另一台 Mac 上由 Athena 创建的工作区，都不在其中。
- 沙箱只在 Athena 运行时回收；应用退出期间到期的沙箱在下次启动后处理。
- 自动化场景可以在启动 Athena 时用环境变量 `WORKBENCH_CODER_URL` 和 `WORKBENCH_CODER_TOKEN` 提供连接。这样的连接只在本次运行有效，不写入磁盘，变量读取后即从进程环境里移除。
- 本机沙箱的网络隔离、资源限制与预览端口的行为没有变化；守护进程见 [athena-sandbox 说明](../packages/athena-sandbox/README.md)。页面改动落到源码时使用的前端、后端沙箱见 [页面改动落到源码](page-changes-to-source.md)。

## 验证范围

- 回收规则和实例管理有单元测试覆盖，并用真实 Docker 验证过：两个自建沙箱的文件互不可见，闲置后停止、再次使用时文件仍在，超过保留期后容器和文件一起移除，保留的那个留下。
- Coder 沙箱在一套本机搭建的 Coder 2.38 部署上，用真实的 Coder CLI 和 SSH 走通（`tests/coder-live.test.ts`）：按模板创建两个工作区并安装守护进程，两边的文件互不可见，执行命令、经端口转发打开预览、导出产物，闲置后两个工作区在 Coder 上停止，再次使用时自动启动且文件仍在，超过保留期后未保留的工作区被删除，退出时运行中的工作区被请求停止。所用模板是带 Node.js 的 Docker 容器，主目录在持久卷上。
- 其他 Coder 版本和其他类型的模板（虚拟机、Kubernetes 等）走的是同一套 Coder 接口和 SSH 通道，没有逐一验证。
- 本机沙箱在设置页的创建、停止、启动、保留、调整规则和删除在真实应用窗口加真实 Docker 上走通。
- Agent 按名称使用自建沙箱的调用路径有测试覆盖；尚未在真实模型对话中验证模型是否稳定地按名称选用。
