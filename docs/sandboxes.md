# 沙箱实例与回收

沙箱是本机 Docker 里的独立环境，用来运行命令、构建项目和启动预览。它不挂载本机项目、登录凭据或 Docker socket，容器以受限权限运行。使用前需要本机已安装并启动 Docker。

沙箱有两个来源：

| 来源 | 怎么出现                                                                       | 归属                             |
| ---- | ------------------------------------------------------------------------------ | -------------------------------- |
| 自建 | 你在「设置 → 沙箱」里命名并创建，可以有多个                                    | 属于你，任何对话都可以点名使用   |
| 对话 | Agent 在任务需要独立环境时自动创建，每个对话按用途最多三个（基础、前端、后端） | 属于那个对话，对话删除时一并回收 |

## 创建和使用

1. 打开「设置 → 沙箱」（或输入 `/settings sandbox`）。
2. 填写名称，选择运行环境，点击「新建」。运行环境有三种：基础 Node、Node 前端、Java 后端。第一次使用某种环境需要先准备镜像，可能要几分钟。
3. 在对话里说出沙箱的名称，例如「在『支付页重构』里把项目跑起来」。Athena 会在这个沙箱里工作；已停止的沙箱在使用时自动启动，文件仍在。
4. 没有点名时，Agent 照常使用对话自己的沙箱。

名称为 1–40 个字符，可用文字、数字、空格和 `. _ -`，不区分大小写且不能重复。自建沙箱最多 20 个。

每个沙箱一行，显示状态、运行环境、来源和回收时间，可以：

- **打开预览**：沙箱里有正在运行的预览服务时，在右侧浏览器打开它。
- **启动 / 停止**：停止只结束进程，文件保留。
- **保留 / 取消保留**：保留的沙箱不会因为长期不用而被删除。
- **删除**：需要再点一次「确认删除文件」，容器和其中的全部文件一起移除，不能恢复。

当前任务正在使用的沙箱不能手动停止或删除，需等任务结束。

## 回收规则

Athena 运行期间每分钟检查一次，规则在同一页的「回收规则」里调整：

| 规则           | 默认    | 可选                             | 做什么                                               |
| -------------- | ------- | -------------------------------- | ---------------------------------------------------- |
| 闲置多久后停止 | 30 分钟 | 15 分钟、30 分钟、1 小时、2 小时 | 停止容器，释放内存和 CPU；文件保留，下次使用自动启动 |
| 多久不用后删除 | 7 天    | 3、7、14、30 天                  | 移除容器和其中的全部文件；标记为保留的沙箱跳过       |
| 同时运行上限   | 4 个    | 2、4、6、8 个                    | 需要启动新的沙箱而名额已满时，先停止最久没用的那个   |

几条边界：

- **正在使用的不动。** 有命令正在执行、当前任务所在的对话正在使用，或它的预览正显示在浏览器当前标签里的沙箱，不会被停止或删除。
- **名额已满且都在使用时拒绝启动。** Athena 不会为了腾位置打断正在进行的工作，而是提示先停止一个或调高上限。一分钟内刚用过的沙箱也不会被挤掉。
- **删除对话时回收它的沙箱。** 只回收 Agent 为这个对话创建的，自建沙箱不受影响。
- **Docker 没有运行时什么都不回收。** 记录保留，等 Docker 恢复后再处理。
- **旧版本留下的沙箱会被列出。** 对应的对话还在的归到该对话名下，对话已删除的标为「对话已删除」，只能删除；两者都按上面的期限回收。

「使用」指 Agent 在沙箱里执行命令、读写文件、启动服务，或你手动启动它。每次使用都重新计时。

需要长期留存的结果不要只放在沙箱里：让 Agent 导出为产物，或把沙箱标记为保留。

## 数据与边界

- 沙箱的记录和回收规则保存在本机用户数据目录的 `sandboxes/instances.json`，仅当前用户可读；沙箱里的文件在同一目录下各自的文件夹里。
- 回收只处理当前用户数据目录创建的沙箱，不会碰本机上其他 Docker 容器。
- 沙箱只在 Athena 运行时回收；应用退出期间到期的沙箱在下次启动后处理。
- 网络隔离、资源限制与预览端口的行为没有变化，见 [沙箱守护进程说明](../packages/athena-sandbox/README.md)。页面改动落到源码时使用的前端、后端沙箱见 [页面改动落到源码](page-changes-to-source.md)。

## 验证范围

- 回收规则和实例管理有单元测试覆盖，并用真实 Docker 验证过：两个自建沙箱的文件互不可见，闲置后停止、再次使用时文件仍在，超过保留期后容器和文件一起移除，保留的那个留下。
- 设置页的创建、停止、启动、保留、调整规则和删除在真实应用窗口加真实 Docker 上走通。
- Agent 按名称使用自建沙箱的调用路径有测试覆盖；尚未在真实模型对话中验证模型是否稳定地按名称选用。
