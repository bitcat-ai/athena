# Athena 用户指南

Athena 把本机 Agent 任务和网页工作区放在同一个 Mac 应用中。当前分发目标是 macOS Apple Silicon；安装与发布状态以 [README](../README.md#下载) 和 [Releases](https://github.com/Dylan-Nihilo/athena/releases) 为准。

## 首次配置

首次启动先展示 Athena 的欢迎开场，动画结束后出现「开始配置」。点击后，大头像收为对话头像，所选选项移到右侧成为你的回复；Athena 按短句呈现说明，选择和实际结果保留在记录中。新内容向上推进，上翻时不会抢回滚动位置，可以用「回到最新」继续。减少动态效果时直接展示可操作状态。

![Athena 首次引导（隔离 UI 测试）](screenshots/onboarding.png)

1. **选择 Agent**：点击「开始配置」后检测本机 AI Agent，以带图标和名称的胶囊选项展示。选择后再核对该 Agent 的连接；只检测到安装不等于已经登录或支持所有能力。暂无可用 Agent 时可查看 Codex 安装计划，确认官方来源、版本、位置及大小后再安装。
2. **连接**：检测到可以启动的本机 CLI 即可继续，沿用它已有的登录、模型服务和环境配置；Athena 不检测登录状态。凭据是否可用以实际连接和对话为准，模型服务拒绝时会在对话中提示。需要时可在「查看连接详情」里通过官方 CLI 登录 Codex 账号，其他 CLI 在终端登录。取消只终止此次发起的登录过程，不注销已有账户。
3. **项目文件夹（可选）**：选择「先不选文件夹」即可继续对话与网页准备；Athena 使用自身私有目录作为运行位置，侧栏显示「不绑定文件夹」。选择真实项目时仍需确认并核对可访问性；取消不替换原目录。目录选择不授予任意文件或整台 Mac 的永久访问权限。
4. **网页工具（可选）**：在同一段对话里检查本机的 Google Chrome。找到后直接启动并打开 Athena 欢迎页；没有找到时提供 Chrome 官网入口，安装后重新检查，Athena 不替你下载或安装浏览器。选择「以后再说」可先进入对话，网页功能仍需单独准备。
5. **进入工作台**：完成宿主核对后，Athena 的最后一句回复自然过渡到主界面；若网页工具已就绪，右侧直接显示可操作的 Athena 欢迎页。可以修改页面标题、切换外观，或照着页面上的三句话让 Athena 直接改这张页面。选择「跳过设置」不会把未完成的连接标为成功，工作台保留「继续准备」入口。

已有数据的用户不会被强制再次引导。在「设置」可以重开；未切换工作目录时，退出保留当前草稿和会话。确认切换目录后，会清空未发送草稿和元素上下文，已有项目对话仍保留。中断或重启后重新核对已确认的条件，不自动重放安装、登录或权限操作。引导本身不调用模型、不生成虚构任务历史。

安装和登录方式见 [Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli#getting-started) 与 [登录命令](https://learn.chatgpt.com/docs/developer-commands#codex-login)。模型请求使用你的 CLI 账户；Athena 不要求把 Codex 密钥粘贴到界面。

网页功能使用本机已安装的 Google Chrome，可在「设置」中改选其他位置的 Chrome。网页执行器是固定版本的 agent-browser：首次启动网页功能时从官方发布下载并校验 SHA-256，校验不通过不会运行。源码开发可先执行 `npm run setup:agent-browser` 准备开发副本；脚本不启动任何进程，也不写入系统 Applications。组成与边界见 [网页执行器](web-executor.md)。

安装 Chrome 后，回到 Athena 即可。Athena 在启动、切回窗口、唤醒和任务开始前复查安装，运行期间也会每 15 秒检查一次。原路径失效时会查找常用目录、macOS 注册应用和 Spotlight 索引。基础配置完成后会在空闲时自动连接，正在执行的任务和共享保留原有状态。首次配置选过「以后再说」也可以随后接入。如果「设置 → 浏览器」提示「已安装，未连接」或「网页工具未连接」，点击「重新连接」。Chrome 和网页执行器都就绪后会显示「已连接」。如果 Chrome 位于未被发现的自定义目录，点击「选择 Chrome」指定位置。

已发布旧包可能采用 ad-hoc 签名；正式签名与公证构建见 [macOS 签名与公证](apple-signing.md)。签名和公证以具体产物验证结果为准，目前没有自动更新。系统提示需要由用户本人处理。

## 首页、对话与草稿

侧栏可新建对话、搜索当前工作区未归档对话的标题和消息，以及进入用量和设置。用户菜单显示本机名字与首字母头像，可切换工作目录和浅色、深色或跟随系统外观；它不是账户或订阅入口。

输入框的「＋」可添加图片、引用工作区文件、选取页面元素或开始录制。工作区文件也可直接拖入输入框。输入 `@` 可查找当前工作区文件，按 Enter 加入草稿。文件以相对路径显示，可以逐项移除。较短的 UTF-8 文本随消息附上发送时的正文，二进制文件和较大的文件作为工作区路径引用，后续读取沿用当前运行时的文件权限。

- Enter 发送，Shift+Enter 换行；中文输入法合成中的 Enter 只用于确认输入。
- 可以点「添加图片」、将图片拖入输入框，或按 ⌘V 粘贴截图。预览后可逐张移除，也可只发送图片。支持 PNG、JPEG、WebP，每条最多 4 张、单张最多 5 MB、合计最多 10 MB。图片随各自草稿保留，发送后随聊天记录保存；不会只复制图片路径作为正文。
- 可用的图片入口取决于当前运行时，还需要所选模型支持图片。切换到不支持图片的运行时会保留草稿并提示处理附件。读取失败的图片可移除后重新粘贴。
- 在同一窗口中，切换或新建对话会保留各自的草稿。第一次发送前的独立草稿可从侧栏「未发送草稿」找回。发送成功只清除已提交的那份文字，发送失败、停止任务或等待回执时继续输入都不会清空新草稿。
- 你发送的消息和 Athena 已结束的回答下方都有复制按钮，可用 Tab 聚焦后按 Enter 或空格触发。复制的是消息正文：回答保留 Markdown 中的链接与代码，不包含页面上下文、工具动作和执行记录。系统剪贴板确认保存完整内容后才提示已复制，否则提示失败原因。
- 移除元素上下文只移除引用，不清空已写文字。
- 点击回答中的网页链接，会展开右侧网页并新建标签页，保留原页面。浏览器未启动时会先启动；失败会提示原因。登录授权、安装和系统服务入口仍按各自用途打开。
- 任务进行中可以继续发送消息。新消息进入发送队列，列在所属对话的输入框上方；前面的任务正常完成后，Athena 按先后顺序逐条发送，每条消息各占一轮。另一个对话有任务在进行时发出的消息同样排队。
- 排队的消息可以「取回编辑」放回输入框，或「移出队列」。任务被你停止或失败后，该对话排队的消息不会自动发出，点击「继续发送」后才继续；其他对话排队的消息不受影响。
- 队列最多 20 条，只保存在本次运行中，退出 Athena 后不保留；切换到其他工作目录期间，原目录下排队的消息会等你回到该目录再发送。归档或删除对话会一并丢弃它排队的消息。
- 切换工作目录需要当前任务先停止；取消系统目录选择器保持原目录。

侧栏每段对话右侧的「…」菜单用于归档和删除；悬停或键盘聚焦到这一行时出现，当前对话始终显示。

- **归档**：对话从主列表和搜索中收起，记录原样保留。有已归档的对话时，「对话」标题旁会出现「已归档」入口。已归档的对话只能查看，不能继续发送，也不会为它准备 CLI 连接；在它的菜单或对话底部点「恢复对话」即可放回主列表继续使用。
- **删除**：在确认框中点「删除对话」后才会执行，取消或按 Esc 不会删除。删除的是 Athena 保存的这段对话记录，删除后无法恢复；本机 CLI 自己保存的会话历史不受影响，用量统计和网页录制也不随之删除。
- 任务还在进行的对话不能归档或删除，请先用停止按钮结束任务或等待完成；Athena 不会为了归档或删除替你停止任务。
- 归档或删除当前打开的对话后回到新对话页面。归档状态和删除结果随对话记录保存，重启后保持一致。
- 已归档的飞书对话不再接收新消息；同一飞书会话之后发来的消息会进入一段新的对话。

## Live 语音

输入框工具栏的麦克风可打开 Athena Live。首次使用时，在「设置 → 语音」保存支持 GPT-Live 的 OpenAI 项目密钥，按系统提示允许麦克风。密钥加密保存在本机。音频发送至 OpenAI，语音费用与后台 Agent 的用量分别计算。**保存密钥之后，点击麦克风即开始通话并计费**；没有密钥时只会提示去设置。

- **只开对话时**，输入框保持原来的外形，写字的位置变成字幕，头像外圈和波形随音量起伏。可以静音、结束通话，或点击地球图标一起看网页。结束通话后回到键盘输入，原来的草稿还在。
- **一起浏览时**，侧栏和对话让出空间，网页占满窗口，通话收成网页下方的一行。字幕浮在网页下缘，只显示正在说的这句，停下几秒后淡出，不挡点击。可以回看对话（通话变为底部小胶囊）或收起网页。切换布局会沿用当前连接和静音状态。
- **指着说**，把指针停在网页的某个元素上，说「把这个改大一点」，Athena 会把指针下的元素一起交给 Agent，并在页面上短暂标出它。
- **让 Athena 做事时**，语音助手把需要操作的请求交给当前对话的 Agent。执行结果回到通话，操作记录保留在对话中。需要审批或补充信息时，对话面板会打开，通话继续。口头同意不会替代界面审批。
- **边做边改口**，任务进行中可以直接再说话，不用等它做完：说「不对，改成蓝色」，Athena 停下手头的任务，从已做到的地方按新说法接着做；说「再把标题加粗」「然后总结一下」，它做完手头的再做这一项；说「停」「算了」，它停下并告诉你；问「好了吗」，它回答进度，不打断任务。
- **只问不改**，问「那个输入框你看到了吗」「是哪个」时，Athena 只在页面上把它标出来并回答。这一句由应用判定为提问后，页面在这一轮是只读的，Agent 无法修改。要修改时，它只改这句话点名的对象和说出的改动；没说改成什么会先问。说上一次改错了对象，它会先撤销那次改动。
- **结束时**，Athena 释放麦克风并请求结束远端通话，停止本次语音发起的运行中任务。连接异常时，界面会显示重试或结束通话的入口。原始音频不保存到工作区；通话字幕只在本次界面显示，交给 Agent 的内容按正常对话保存。

## 任务、模型与结果

任务计划、执行过程、审批、补充信息和人工接管都在对应对话的交互面板中处理。后台对话需要处理时，侧栏会标记等待状态；进入该对话核对后操作。

App 的复制成功、操作错误、连接异常和版本更新显示在右上角。普通提醒自动消失，悬停或键盘聚焦时保留，可用关闭按钮或聚焦后的 Esc 收起；不会抢走输入焦点。它们与 Agent 交互面板独立，不会代替审批或人工确认。

Athena 会检查本机 Codex CLI 的官方稳定版。发现新版本时会显示当前版本、最新版本和「查看更新说明」。收起后同一版本不再主动提醒，仍可在「设置」的 Codex 版本行打开发布说明。更新由你自行安装。

在「设置」选择新对话默认 CLI；输入栏的 Agent 菜单可为新对话改选 CLI，已有执行记录的对话不会迁移到其他 CLI。旧档案未记录执行器的对话继续使用 Codex。未安装时，请在终端安装后刷新；登录与模型服务配置沿用 CLI 自身的设置，不会自动安装或切换。

「运行时配置」顶部跟随当前查看的对话，显示对应 CLI 的状态、版本、位置和下次任务模型；本轮或最近执行模型单独显示，以 CLI 回报为准，未回报时显示「CLI 未报告」。下方「新对话默认配置」管理默认运行时与默认模型；未单独选模型的对话沿用该 CLI 的默认模型。安装检测列表收在「本机 CLI 检测详情」中。

点击当前运行时旁的「切换」可选择其他可用 CLI。尚未绑定 CLI 会话的空对话直接切换；有消息或已建立原生会话时新建对话，原记录保留，新对话默认配置不变。任务运行中不可切换。

需要使用所选 CLI 自己的交互命令、插件或终端界面时，点「打开原生会话」。它在当前工作目录启动独立窗口，并沿用 CLI 自己的登录与权限。在普通 Codex 对话里也可直接请求生成图片；账号和 Provider 支持时会出现图片预览与「在访达中显示」。

当前源码支持 Codex、Claude Code、Pi、OpenCode 和 Kimi 使用右侧网页的观察、导航、点击、填写、元素预览与撤销能力。Pi 的本地文件和命令工具仍逐项请求确认；Claude 保留原生只读文件与 Skill 工具，写入和命令工具关闭。Gemini、Cursor 尚未接通网页工具，Cursor 继续限只读任务；OpenCode 1.x 通过 ACP 接入，文件和命令操作需逐次确认。各 CLI 的真实模型验收及限制见 [本机 CLI 适配](mainstream-cli-support.md)。

输入框的 Agent 按钮显示当前服务图标，悬停可查看名称。连接状态对应当前工作目录里的这段对话。同一对话就绪后会复用现有 CLI 会话；打开模型选择器无需重新登录。即使某段历史会话无法恢复，也可以单独刷新模型目录。

点击输入框旁的模型名称，直接在列表中选择模型。若模型支持调整推理强度，在同一面板拖动滑块，或聚焦滑块后用方向键逐档调整。可选模型与档位来自本机 CLI。设置用于后续任务，任务进行中不可调整；应用会区分所选配置与本轮实际执行记录，不使用模型自述代替证明。

执行面板显示公开计划、工具动作、结果核对、人工请求和文件产物。命令、文件或额外权限需要批准时，在 Athena 桌面界面确认；结构化提问也在桌面回答。

停止按钮用于中止当前任务。结果未知时应先查看页面或回执并继续核对，避免重复提交。直接手动浏览或切换标签会使旧观察与排队动作失效，但不等于停止整轮任务。

更多执行与恢复约束见 [复杂网页任务](complex-web-tasks.md)；模型证据与用量口径见 [Agent 交互与用量](agent-experience.md)。

### Skills、MCP 与命令

「设置 → Skills」列出当前 CLI 的原生 Skills 与本机/项目共享 Skills，支持搜索、查看来源和加入任务。输入 `$` 可直接选择 Skill，输入 `/` 可查看命令和 Skills。同名条目用 `skill:` 或 `local:` 区分来源，最多选择三个。宿主发送前重新核对来源与可用性。

「设置 → MCP」读取 Codex、Claude、Cursor、Gemini、Kimi 和 OpenCode 的已有本机配置。点击「连接」后才能在任务中使用；不会改写原 CLI 配置。连接通过已安装的 Codex 原生 MCP 运行时，保留 Codex 的 OAuth 身份；其他 CLI 的专用 OAuth 登录不能直接移植。写入或未声明只读的工具会显示具体审批，停止后不重放未知结果。结果不确定时先在原服务核对，再选择「核对后重连」。

| 命令                             | 作用                                                                    |
| -------------------------------- | ----------------------------------------------------------------------- |
| `/new`                           | 新建对话，保留历史                                                      |
| `/model`、`/model 模型名称`      | 打开模型选择，或使用目录中实际支持的模型                                |
| `/agent`、`/agent codex`         | 选择可用 CLI；已有执行会话不搬迁                                        |
| `/skills`、`/mcp`                | 打开对应设置                                                            |
| `/settings`、`/settings browser` | 打开设置；分类为 agent、browser、skills、mcp、sandbox、feishu、learning |
| `/usage`                         | 查看真实用量与估算                                                      |
| `/browser`、`/browser hide`      | 显示或收起右侧浏览器                                                    |
| `/stop`                          | 停止当前执行                                                            |
| `/help`                          | 查看命令与键盘帮助                                                      |

这些命令直接执行对应操作，不作为普通消息发给模型。方向键选择、Enter 确认、Esc 关闭；输入法确认不会提交。未接入的终端专用命令不会被伪装成原生能力。

创建新网页使用独立预览页，原页面保留。用户滚动查看时，内容读取和 DOM 预览可以继续；点击、输入、导航、停止与不确定结果遵守 [浏览器交互协议](browser-interaction-protocol.md)。

「本机 Agent → 快速页面初稿」默认关闭。开启后，本机 Claude 的 Sonnet 可用于并行首屏，当前 Agent 继续完善；额外模型调用会独立计入用量。它不代替浏览器协议与结果核对。

## 浏览网页与调整元素

1. 打开浏览器，在地址栏输入 HTTP(S) 地址。使用标签栏或 `⌘T` 新建页，`⌘W` 关闭活动页，`⌘L` 定位地址栏。
2. 点击「选取元素」，悬停查看边界和尺寸，再点击目标。选取本身不会触发目标按钮；Esc 取消选取。
3. 在元素工作区调整数值、颜色、间距、文字、样式或动效，查看即时预览；每组连续调整可撤销。
   也可让支持网页工具的 Agent 在当前容器内或元素前后创建内容，例如卡片、标题、链接和搜索框。新元素可继续选中、修改；新增输入控件不会提交到网页原有表单。撤销会保护后来输入或被网页修改的内容，必要时提示先处理后续改动。
   不选元素也可以直接让 Agent 改外观或文案，例如「把"立即开始"按钮改成蓝色圆角」「把整个页面改成 Apple 风格」「把标题改成……」。每轮任务开始时 Athena 会把当前页面的结构概览（标签、id、类名、文字和主要样式，不含敏感输入框、内嵌子页面与 Shadow DOM 内部）交给 Agent，Agent 据此一次调用完成整份改动：样式以一张附加样式表生效，不改动页面节点，页面自行重新渲染后仍然保留；文案按选择器替换。这类改动无需确认、即刻生效，随后由光标演示，Agent 不等演示结束就继续；一次撤销收回整份改动，其间被页面自己改写过的文字保持不动。样式表不能加载任何外部资源（网络图片、字体、`@import`），只接受颜色、渐变和内联的 `data:` 图片；不作用于内嵌子页面和 Shadow DOM 内部；选择器没有命中、规则被更高优先级的样式盖住时，结果会如实告诉 Agent。
   Agent 修改或撤销元素时，彩色光标会落在改动处。改文字有逐字输入，改样式有选框和间距标线，新增内容会逐块画出。把两个元素并排、改回上下布局或撤销时，两个光标会分别指向这两个元素。你在检查器里拖动控件时可以连续查看实际效果，松手提交后出现一个不带 Athena 名签的光标。没有产生变化或操作失败时不会播放成功动画。

   整页换风格能逐屏演示。独立页面脚本和每段 `web_run` 的第一次页面求值可以使用这个效果。后续连续修改使用短光标标出已检测到的变化，多处同时改动会合并呈现。动画期间 Agent 就能读取结果；短光标不占用鼠标或键盘。截取任务证据、停止任务或手动接管会结束演示。系统开启「减弱动态效果」时直接显示结果。

   逐屏演示最多覆盖约 16 屏，跟随文档自身的滚动。正常播放完会回到起始位置，手动接管时停在当前位置。整页快照超过约 3 秒就会释放，脚本之后返回时仍可标出检测到的修改。脚本反馈以当前主体页面可观察的节点变化和有限的视口采样为依据，内嵌页面、画布内部像素或尚未渲染的内容可能无法定位。
4. 若要持久修改项目，使用「修改源码」把元素引用与预览变更带入对话，或直接在对话里要求把页面上的改动落到源码。Athena 会把页面上仍然显示的预览改动（你自己调的和 Agent 改的）逐条记录下来，按知识库定位这个页面的代码仓库，在前后端各自的沙箱里修改并构建真实代码，见 [页面改动落到源码](page-changes-to-source.md)。页面来自当前工作目录里的项目时，Agent 直接修改工作目录的文件并验证。

想自己动手时，可以让 Athena 带做，例如「教我怎么在这个后台开通企业邮箱，我自己来点」。Athena 在页面上逐步高亮该点哪里、该填什么，旁边的说明卡写明这一步做什么，点击和输入都由你完成；对话里同时列出步骤和进度。说明卡上可以随时「结束」、回到「上一步」、「跳过」当前一步，或把剩下的「交给 Athena」。流程跨页面时说明会跟到新页面。你填写的内容不会被读取或交给 Agent，它只知道每一步是否完成。登录、付款、最后确认这类只应由你完成的步骤，Agent 也会主动带做而不是代劳。一次最多 12 步，不进入内嵌的子页面，15 分钟没有走完会自动结束，共享期间不可用。细节见 [带做](guide.md)。

**页面预览只修改当前 DOM，刷新后恢复；修改源码才会改变项目文件。** 远端网站与代码仓库的对应关系需要你确认一次后才会记住，Athena 不会猜测。复杂子节点和敏感内容存在编辑限制；外链脚本不属于预览接口，整页预览的样式表不能加载外部资源。

创建结构每次最多 80 个节点、嵌套 8 层。高级脚本和文件上传仍需要在 Athena 内确认；停止、手动接管和共享期间的控制边界不变。技术实现与本轮验证范围见 [网页工具联动](native-browser-interop.md)。

Chrome 以独立后台进程运行，使用 Athena 专用的 profile，与日常浏览器的登录和数据互不相通；页面画面、鼠标、键盘、中文输入和滚动都位于 Athena 窗口。默认按需要适应宽度，也可切换到 100%；画面等比显示，尺寸未同步时不会接受过期坐标点击。

普通 DOM、开放 Shadow DOM 与受支持 iframe 可被选取。closed Shadow DOM、Canvas/WebGL 内部绘制对象不是可直接定位的 DOM 节点；旋转或 3D 变换 iframe 的精确坐标操作有明确限制。细节见 [元素交互核验](element-interaction-research.md)。

## 记忆：让 Athena 记住你的做法

在对话里提出的长期要求（例如「以后改文案不要动按钮文字」「回答先说结论」）和任务中确认过的事实，Athena 会记下来并带进之后的对话。每一条都必须对得上你本人在对话里的原话、你的操作（撤销预览、拒绝确认、停止任务、确认结果）或资料出处，网页内容不能充当依据。

在「设置 → 记忆」查看全部内容和各自的依据，逐条停用或删除，或整体关闭「从对话中学习」。同一页还列出已确认的页面与代码仓库对应关系。「导出文档」把这些内容连同依据整理成一份 Markdown 文档，便于核对后归入团队知识库；文档只写到你选择的本地位置。

记忆里的内容不扩大任何授权，也不替代本轮的明确指令。是否记录、如何概括由模型判断，请定期查看。细节见 [记忆：从使用中学习](learning.md)。

## 沙箱

需要一个不碰本机项目的独立环境时，在「设置 → 沙箱」创建沙箱：填写名称，选择基础 Node、Node 前端或 Java 后端环境，可以同时有多个。在对话里说出名称，Athena 就在那个沙箱里运行命令、构建和启动预览。沙箱运行在本机 Docker 中，不挂载本机项目和凭据。

沙箱会自动回收：默认闲置 30 分钟后停止（文件保留，下次使用自动启动），7 天不用后连同文件一起删除，同时最多运行 4 个。三项都可以在同一页调整；标记为「保留」的沙箱不会被删除，正在使用的沙箱不受影响。Agent 为某个对话自动创建的沙箱也列在这里，对话删除时一并回收。细节见 [沙箱实例与回收](sandboxes.md)。

## 录制与页面共享

网页录制保存步骤、元素目标、编辑与撤销信息，可查看、导出 JSON 并交给 Agent 分析。它不等于完整测试用例生成或页面状态复原；导出前应检查其中的页面内容。

1. 在网页上开始录制，亲手完成一次操作后结束。在「操作记录」点「让 Agent 理解这段操作」。当前可选用本机 Codex、Claude Code 或支持相应隔离参数的 Pi 生成流程草稿。点草稿里的步骤编号可以回到当时的操作。旧版录制也可以重新分析，未采到的结果会保留为未知。
2. 查看模型建议的可变对象，回答或纠正草稿中的问题。例如，在导出客户材料的流程里，可以说明内部备注是否允许对外发送。更换对象时，请确认这些规则也适用于新对象。
3. 打开同一网站上的流程起始页面，在录制详情中填入原对象及新对象，点「开始带做」。Athena 指出控件，由你亲自点击或填写。练习期间可以停止；页面或行目标无法唯一确定时重新核对。带做支持最多 12 步。
4. 如需核验，可以指定最后预期出现的页面提示，或选择「核验客户材料 ZIP」。后者按 Meridian 示例格式在本机检查客户编号与四份材料，可另选排除内部备注。页面提示通过仅表示观察到指定文字。跳过必要步骤、缺少能关联的产物或证据不足时，不会报告业务成功。

在右侧网页工具栏点「共享」。选「发起共享」可邀请他人查看当前网页，选「加入共享」可粘贴收到的邀请。双方需要可互通的局域网或 VPN。Athena 在隔离窗口核对邀请中的证书指纹，受邀者填写称呼后仍需主持人确认。

- **仅查看**：接收页面画面，不能输入或修改。
- **可操作**：具备操作资格，仍需单独获得当前控制权。
- **当前控制者**：拥有本轮页面输入权；主持人可以交接或收回控制权。
- 共享结束后保留可查看的操作记录，邀请和本次连接不再有效。

共享期间 Agent 不接管页面；应先结束共享再运行 Agent。详细网络、权限和验证范围见 [共享工作区页面](shared-workspace.md)。

## 用量与费用

独立「用量」页以 **USD API 等价估算和每日 USD 图** 为主，Token、输入/输出与缓存明细为补充，可按时间、模型、助手和日期筛选。

估算采用已有公开费率与真实采集字段，不代表订阅实际扣费。缺少费率、模型或必要用量字段时显示未知或部分数据；实际零值不会与缺失数据混为一谈。旧任务没有可信记录时不按聊天文本补算。

「估算依据与单价」提供定价口径与来源；详细技术说明见 [交互体验修正](interaction-refinement.md)。

## 飞书

在「知识库资料」保存一个飞书 Wiki 或文档入口后，可以让 Athena 检索规范、使用独立沙箱准备源码，并通过 Neo 操作构建页面。资料读取使用本机 `lark-cli` 用户授权，与下面的机器人消息连接独立。使用方式、真实与模拟验收范围见 [从飞书知识库到前端构建](frontend-build-workflow.md)。

针对已有网页，可以选中一个元素并描述新增功能：先查看可撤销的页面预览，再将需求记录为 PRD，随后进入仓库定位、前后端独立沙箱实现与复测。仓库由 Agent 从知识库查到后经你确认登记，无需额外配置，见 [页面改动落到源码](page-changes-to-source.md)；外部仓库服务的配置、演示资料边界和验收方式见 [客户材料导出链路](customer-export-workflow.md)。

在「设置 → 飞书」创建专用机器人，扫码确认后，向机器人私聊发送桌面显示的 `绑定 WB-…` 完成操作者配对。具体步骤见 [飞书连接指南](feishu-setup.md)。

已有功能支持配对单聊入口、已配对本人在群聊里 @ 机器人发起任务（结果回复到该群）、飞书任务的待处理提醒和停止请求；审批及结构化回答仍在 Mac 上完成。在 Athena 桌面端发起的对话不会发到飞书。需要 Mac 保持开机、联网且 Athena 运行，没有云端代跑，也不承诺离线消息补发。

扫码创建、长连接、配对和加密配置恢复有既有验证记录；**外部飞书触发 Agent 并回传最终结果、真实通知投递的完整联调仍有未验证项**，不能把本地模拟测试写成外部闭环已完成。

## 数据与凭据

| 内容               | 存放与边界                                                       |
| ------------------ | ---------------------------------------------------------------- |
| 设置、聊天、录制   | Electron `userData/workspace.json`，普通工作区数据不是加密数据库 |
| 独立用量           | `userData/usage.json`，保留真实统计与缺失状态，不包含隐藏推理    |
| 飞书凭据与绑定     | 使用 Electron `safeStorage` 加密；macOS 系统密钥存储保护密钥     |
| Codex 登录         | 由官方 CLI 管理，Athena 复用既有登录                             |
| 浏览器 profile     | Athena 独立管理，不属于飞书凭据加密范围                          |
| 网页任务记录       | `userData/agent-browser/`，输入值与网址参数不落盘                |
| 记忆里的规范与知识 | `userData/learning/learning.json`，仅当前用户可读，不记录凭据    |
| 沙箱记录与文件     | `userData/sandboxes/`，记录仅当前用户可读；文件随沙箱回收而删除  |

为兼容现有数据，保留以下标识，不应因产品名称变化而重命名：

- 应用 ID：`app.agent.workbench`。
- macOS 默认数据目录：`~/Library/Application Support/Agent Workbench/`。
- `WORKBENCH_*` 环境变量、`workbench:*` IPC、`workbench_browser_*` 工具标识及既有钥匙串身份。

更新本地签名可能触发系统钥匙串授权。恢复超时后应用保留原配置，并提供重试；应由用户本人处理授权，不需要自动重建机器人。

录制会遮罩识别出的敏感输入，但不是全站数据脱敏。分享 JSON、文字或截图前应自行检查；提供给 Agent 的上下文可能进入所选模型服务。不要把凭据、profile、inbox 或真实用户数据提交到 Git；自定义 `WORKBENCH_USER_DATA_DIR` 应放在仓库外。

## 开发环境与验证

需要 Node.js 22.12+ 和 npm。安装前，在用户级 `~/.npmrc` 中配置 CollectUI 分发的 HugeIcons Pro npm key，保留文件内其他已有配置：

```ini
@hugeicons-pro:registry=https://npm.collectui.pro/
//npm.collectui.pro/:_authToken=YOUR_COLLECTUI_TOKEN
```

仅在本机将 `YOUR_COLLECTUI_TOKEN` 替换为真实 Key，并设置 `chmod 600 ~/.npmrc`。仓库 `.npmrc` 仅保留 registry，不保存 Token 或鉴权环境变量占位。pnpm 不展开仓库控制的鉴权环境变量；如需使用环境变量，应在用户级配置中引用。CI 可使用临时用户配置文件。不要提交用户配置或在聊天、日志中输出真实 Key。

```bash
npm ci
npm run setup:agent-browser
npm run dev
```

`npm ci` 的 postinstall 执行 [HeroUI Pro 安装脚本](../scripts/setup-heroui-pro.mjs)：先检查完整构件，再尝试授权缓存；无可用缓存时需要通过环境变量私下配置 `HEROUI_KEY`，然后运行 `npm run heroui:setup`。脚本不会自动读取项目 `.env` 文件；不要把密钥写进仓库或命令输出。

开发窗口使用 Vite 热更新界面。主进程、preload 及其导入的代码变更后，开发服务会重新构建并重启 Electron；有未发送草稿、队列、运行中任务、录制、共享或其他应用窗口时，会等到空闲再重启。构建报错时可继续使用上一版窗口，修正后会自动加载。手动退出 Athena 会同时结束本次开发服务。

构建与基础检查：

```bash
npm run typecheck
npm test
npm run build
npm start
npm run package
```

`npm run package` 默认生成 `release/` 下的本机 ad-hoc 签名应用目录。`npm run package:signed` 使用 Developer ID 签名但不公证；`npm run package:release` 需要钥匙串公证凭据，生成签名和公证后的 DMG/ZIP。配置与验证见 [macOS 签名与公证](apple-signing.md)。发布上传、可下载性需要单独验证，目前没有自动更新。

隔离 UI 检查可按改动选择：

```bash
npx tsx tests/homepage-ui.e2e.ts
npx tsx tests/interaction-controls.e2e.ts
npx tsx tests/usage-currency-ui.e2e.ts
npx tsx tests/attention.e2e.ts
npx tsx tests/message-queue.e2e.ts
npx tsx tests/workbench.e2e.ts
npx tsx tests/onboarding-ui.e2e.ts
npx tsx tests/onboarding.e2e.ts
```

这些测试的前提和输出以脚本为准，Electron 联调需先构建。真实 Codex 集成检查（如 `npm run test:live-agent`）会调用模型；不要把它与模拟 CLI/IPC 的界面检查混在一起，也不要无授权地发真实飞书消息。

前端实现遵循 [DESIGN.md](../DESIGN.md)，工程协作遵循 [AGENTS.md](../AGENTS.md)。第三方依赖许可见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)；仓库自身保持 UNLICENSED，HeroUI Pro 构建需要有效商业授权。

## 能力与验证边界

- 浏览器工作流和本机文件修改已有实现；它们不代表所有网站都兼容。
- 桌面 Computer Use 仍在调研，未实现通用 Mac 应用控制或隔离桌面控制。
- CLI 支持与各自的验收边界见 [本机 CLI 适配](mainstream-cli-support.md)；本机 MCP 可读取并连接，通用配置编辑、完整多 Agent 调度、账户/订阅服务尚未实现。
- 已有内部网页工具链不等于任意第三方 MCP 服务都可接入。
- 登录、验证码、支付、外部 OAuth 弹窗和其他敏感流程不得从普通网页验收外推。
- 录制分析尚不提供一键完整 Playwright 测试、PRD 覆盖率报告或后端状态复原。

当前范围与后续研究以 [Computer Use 交接](computer-use-handoff.md) 为准；需要方案、许可和官方来源时再读 [调研报告](computer-use-research.md)。截图必须来自实际应用，Figma 设计稿不能证明功能已经运行。

## 页面建议与风格

网页加载完成后，Athena 会先读一遍页面结构。输入框上方出现「已读完这一页」和最多三条建议，例如带你填表单、整理表格、总结正文；点击后填入输入框，按回车发送。让 Agent 修改页面上的某个元素时，它可以直接动手，不必先查询页面。

浏览器工具行的「风格」可把当前页面切换为夜间、杂志、线框或专注，选「原样」恢复。风格只是页面预览，不会修改网站或源码。
