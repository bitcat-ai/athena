# Athena 用户指南

Athena 把本机 Codex 任务和 BrowserOS neo 网页工作区放在同一个 Mac 应用中。当前分发目标是 macOS Apple Silicon；安装与发布状态以 [README](../README.md#下载) 和 [Releases](https://github.com/Dylan-Nihilo/athena/releases) 为准。

## 首次配置

首次启动先展示 Athena 的欢迎开场，动画结束后出现「开始配置」。点击后，大头像收为对话头像，所选选项移到右侧成为你的回复；Athena 按短句呈现说明，选择和实际结果保留在记录中。新内容向上推进，上翻时不会抢回滚动位置，可以用「回到最新」继续。减少动态效果时直接展示可操作状态。

![Athena 首次引导（隔离 UI 测试）](screenshots/onboarding.png)

1. **选择 Agent**：点击「开始配置」后检测本机 AI Agent，以带图标和名称的胶囊选项展示。选择后再核对该 Agent 的连接；只检测到安装不等于已经登录或支持所有能力。暂无可用 Agent 时可查看 Codex 安装计划，确认官方来源、版本、位置及大小后再安装。
2. **连接与登录**：优先复用所选 CLI 的已有配置。Codex 可通过官方 CLI 打开登录页；Cursor 提供可复制的本机登录命令，其他 CLI 按提示在终端准备。返回后重新检查，点击核对不代表登录成功。取消只终止此次发起的登录过程，不注销已有账户。
3. **项目文件夹（可选）**：选择「先不选文件夹」即可继续对话与网页准备；Athena 使用自身私有目录作为运行位置，侧栏显示「不绑定文件夹」。选择真实项目时仍需确认并核对可访问性；取消不替换原目录。目录选择不授予任意文件或整台 Mac 的永久访问权限。
4. **网页工具（可选）**：在同一段对话里准备 BrowserOS neo。复用已有安装，或先确认安装计划再下载；实际就绪后打开 Athena 欢迎页。选择「以后再说」可先进入对话，网页功能仍需单独准备。
5. **进入工作台**：完成宿主核对后，Athena 的最后一句回复自然过渡到主界面；若网页工具已就绪，右侧直接显示可操作的 Athena 欢迎页。可以修改页面标题、切换外观和探索示例。选择「跳过设置」不会把未完成的连接标为成功，工作台保留「继续准备」入口。

已有数据的用户不会被强制再次引导。在「设置与连接」可以重开；未切换工作目录时，退出保留当前草稿和会话。确认切换目录后，会清空未发送草稿和元素上下文，已有项目对话仍保留。中断或重启后重新核对已确认的条件，不自动重放安装、登录或权限操作。引导本身不调用模型、不生成虚构任务历史。

安装和登录方式见 [Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli#getting-started) 与 [登录命令](https://learn.chatgpt.com/docs/developer-commands#codex-login)。模型请求使用你的 CLI 账户；Athena 不要求把 Codex 密钥粘贴到界面。

普通 Chrome 不能替代 BrowserOS neo。源码开发可执行 `npm run setup:browseros` 下载并校验项目固定版本；脚本不启动浏览器，也不写入系统 Applications。

已发布旧包可能采用 ad-hoc 签名；正式签名与公证构建见 [macOS 签名与公证](apple-signing.md)。签名和公证以具体产物验证结果为准，目前没有自动更新。系统提示需要由用户本人处理。

## 首页、对话与草稿

侧栏可新建对话、搜索当前工作区未归档对话的标题和消息，以及进入用量和设置。用户菜单显示本机名字与首字母头像，可切换工作目录和浅色、深色或跟随系统外观；它不是账户或订阅入口。

输入框的「＋」用于当前网页、元素选取和网页录制，不是文件附件上传入口。浏览器未就绪时，元素选取和录制会显示为不可用。

- Enter 发送，Shift+Enter 换行；中文输入法合成中的 Enter 只用于确认输入。
- 在同一窗口中，切换或新建对话会保留各自的草稿。第一次发送前的独立草稿可从侧栏「未发送草稿」找回。发送成功只清除已提交的那份文字，发送失败、停止任务或等待回执时继续输入都不会清空新草稿。
- 你发送的消息和 Athena 已结束的回答下方都有复制按钮，可用 Tab 聚焦后按 Enter 或空格触发。复制的是消息正文：回答保留 Markdown 中的链接与代码，不包含页面上下文、工具动作和执行记录。系统剪贴板确认保存完整内容后才提示已复制，否则提示失败原因。
- 移除元素上下文只移除引用，不清空已写文字。
- 任务进行中可编辑下一份草稿，但不会自动创建发送队列；停止后可自行决定是否发送。
- 切换工作目录需要当前任务先停止；取消系统目录选择器保持原目录。

侧栏每段对话右侧的「…」菜单用于归档和删除；悬停或键盘聚焦到这一行时出现，当前对话始终显示。

- **归档**：对话从主列表和搜索中收起，记录原样保留。有已归档的对话时，「对话」标题旁会出现「已归档」入口。已归档的对话只能查看，不能继续发送，也不会为它准备 CLI 连接；在它的菜单或对话底部点「恢复对话」即可放回主列表继续使用。
- **删除**：在确认框中点「删除对话」后才会执行，取消或按 Esc 不会删除。删除的是 Athena 保存的这段对话记录，删除后无法恢复；本机 CLI 自己保存的会话历史不受影响，用量统计和网页录制也不随之删除。
- 任务还在进行的对话不能归档或删除，请先用停止按钮结束任务或等待完成；Athena 不会为了归档或删除替你停止任务。
- 归档或删除当前打开的对话后回到新对话页面。归档状态和删除结果随对话记录保存，重启后保持一致。
- 已归档的飞书对话不再接收新消息；同一飞书会话之后发来的消息会进入一段新的对话。

## 任务、模型与结果

任务等待审批、回答或人工接管时，工作台顶栏下会出现提醒。点「查看审批」「去回答」或「查看任务」进入对应对话，核对详情后再处理。收起提醒后，仍可在该对话中处理待办。

Athena 会检查本机 Codex CLI 的官方稳定版。发现新版本时会显示当前版本、最新版本和「查看更新说明」。收起后同一版本不再主动提醒，仍可在「设置与连接」的 Codex 版本行打开发布说明。更新由你自行安装。

在「设置与连接」选择新对话默认 CLI；输入栏的 Agent 菜单可为新对话改选 CLI，已有执行记录的对话不会迁移到其他 CLI。旧档案未记录执行器的对话继续使用 Codex。未安装或需要登录时，请在终端处理后刷新，不会自动安装或切换。

当前包含 Codex、Pi、Claude Code、Gemini CLI 和 Cursor Agent 的协议适配。Pi 的本地工具逐项请求确认；Claude Code 限文本任务，Cursor 限只读任务，浏览器工具仍仅向 Codex 开放。Pi 与 Claude 的隔离真实模型验证已通过；Cursor 登录未就绪、Gemini 未安装，尚未完成其真实模型验收。OpenCode 仍只检测安装。详细能力与验证状态见 [本机 CLI 适配](mainstream-cli-support.md)。

输入框的 Agent 按钮显示当前服务图标，悬停可查看名称。连接状态对应当前工作目录里的这段对话。同一对话就绪后会复用现有 CLI 会话；打开模型选择器无需重新登录。即使某段历史会话无法恢复，也可以单独刷新模型目录。

点击输入框旁的模型名称，直接在列表中选择模型。若模型支持调整推理强度，在同一面板拖动滑块，或聚焦滑块后用方向键逐档调整。可选模型与档位来自本机 CLI。设置用于后续任务，任务进行中不可调整；应用会区分所选配置与本轮实际执行记录，不使用模型自述代替证明。

执行面板显示公开计划、工具动作、结果核对、人工请求和文件产物。命令、文件或额外权限需要批准时，在 Athena 桌面界面确认；结构化提问也在桌面回答。

停止按钮用于中止当前任务。结果未知时应先查看页面或回执并继续核对，避免重复提交。直接手动浏览或切换标签会使旧观察与排队动作失效，但不等于停止整轮任务。

更多执行与恢复约束见 [复杂网页任务](complex-web-tasks.md)；模型证据与用量口径见 [Agent 交互与用量](agent-experience.md)。

## 浏览网页与调整元素

1. 打开浏览器，在地址栏输入 HTTP(S) 地址。使用标签栏或 `⌘T` 新建页，`⌘W` 关闭活动页，`⌘L` 定位地址栏。
2. 点击「选取元素」，悬停查看边界和尺寸，再点击目标。选取本身不会触发目标按钮；Esc 取消选取。
3. 在元素工作区调整数值、颜色、间距、文字、样式或动效，查看即时预览；每组连续调整可撤销。
4. 若要持久修改项目，使用「修改源码」把元素引用与预览变更带入对话。Codex 仍需核对网页与本机项目的对应关系，再修改文件并验证。

**页面预览只修改当前 DOM，刷新后恢复；修改源码才会改变项目文件。** 任意远端网站不会自动对应到本机源码。复杂子节点和敏感内容存在编辑限制；外链脚本、任意样式表注入不属于预览接口。

BrowserOS neo 以独立后台进程运行，使用专用 profile；页面画面、鼠标、键盘、中文输入和滚动都位于 Athena 窗口。默认按需要适应宽度，也可切换到 100%；画面等比显示，尺寸未同步时不会接受过期坐标点击。

普通 DOM、开放 Shadow DOM 与受支持 iframe 可被选取。closed Shadow DOM、Canvas/WebGL 内部绘制对象不是可直接定位的 DOM 节点；旋转或 3D 变换 iframe 的精确坐标操作有明确限制。细节见 [元素交互核验](element-interaction-research.md)。

## 录制与页面共享

网页录制保存步骤、元素目标、编辑与撤销信息，可查看、导出 JSON 并交给 Agent 分析。它不等于完整测试用例生成或页面状态复原；导出前应检查其中的页面内容。

共享入口邀请他人加入**当前网页**，不是共享整台 Mac。双方需要可互通的局域网或 VPN，受邀者需主持人确认后加入，并核对共享证书指纹。

- **仅查看**：接收页面画面，不能输入或修改。
- **可操作**：具备操作资格，仍需单独获得当前控制权。
- **当前控制者**：拥有本轮页面输入权；主持人可以交接或收回控制权。
- 共享结束后保留可查看的操作记录，邀请和本次连接不再有效。

共享期间 Agent 不接管页面；应先结束共享再运行 Agent。详细网络、权限和验证范围见 [共享工作区页面](shared-workspace.md)。

## 用量与费用

独立「用量」页以 **USD API 等价估算和每日 USD 图** 为主，Token、输入/输出与缓存明细为补充，可按时间、模型、助手和日期筛选。

估算采用已有公开费率与真实采集字段，不代表订阅实际扣费。缺少费率、模型或必要用量字段时显示未知或部分数据；实际零值不会与缺失数据混为一谈。旧任务没有可信记录时不按聊天文本补算。

「估算依据与单价」提供定价口径与来源；详细技术说明见 [交互体验修正](interaction-refinement.md)。

## 飞书

在「设置与连接 → 飞书」创建专用机器人，扫码确认后，向机器人私聊发送桌面显示的 `绑定 WB-…` 完成操作者配对。具体步骤见 [飞书连接指南](feishu-setup.md)。

已有功能支持配对单聊入口、任务状态通知和停止请求；审批及结构化回答仍在 Mac 上完成。需要 Mac 保持开机、联网且 Athena 运行，没有云端代跑，也不承诺离线消息补发。

扫码创建、长连接、配对和加密配置恢复有既有验证记录；**外部飞书触发 Agent 并回传最终结果、真实通知投递的完整联调仍有未验证项**，不能把本地模拟测试写成外部闭环已完成。

## 数据与凭据

| 内容             | 存放与边界                                                       |
| ---------------- | ---------------------------------------------------------------- |
| 设置、聊天、录制 | Electron `userData/workspace.json`，普通工作区数据不是加密数据库 |
| 独立用量         | `userData/usage.json`，保留真实统计与缺失状态，不包含隐藏推理    |
| 飞书凭据与绑定   | 使用 Electron `safeStorage` 加密；macOS 系统密钥存储保护密钥     |
| Codex 登录       | 由官方 CLI 管理，Athena 复用既有登录                             |
| 浏览器 profile   | Athena 独立管理，不属于飞书凭据加密范围                          |

为兼容现有数据，保留以下标识，不应因产品名称变化而重命名：

- 应用 ID：`app.agent.workbench`。
- macOS 默认数据目录：`~/Library/Application Support/Agent Workbench/`。
- `WORKBENCH_*` 环境变量、`workbench:*` IPC、`workbench_browser_*` 工具标识及既有钥匙串身份。

更新本地签名可能触发系统钥匙串授权。恢复超时后应用保留原配置，并提供重试；应由用户本人处理授权，不需要自动重建机器人。

录制会遮罩识别出的敏感输入，但不是全站数据脱敏。分享 JSON、文字或截图前应自行检查；提供给 Agent 的上下文可能进入所选模型服务。不要把凭据、profile、inbox 或真实用户数据提交到 Git；自定义 `WORKBENCH_USER_DATA_DIR` 应放在仓库外。

## 开发环境与验证

需要 Node.js 22.12+ 和 npm。安装前，在用户级 `~/.npmrc` 中配置 CollectUI 分发的 HugeIcons Pro npm key，保留文件内其他已有配置：

```ini
@hugeicons-pro:registry=https://npm.collectui.pro/
//npm.collectui.pro/:_authToken=YOUR_COLLECTUI_TOKEN
```

仅在本机将 `YOUR_COLLECTUI_TOKEN` 替换为真实 Key，并设置 `chmod 600 ~/.npmrc`。仓库 `.npmrc` 仅保留 registry，不保存 Token 或鉴权环境变量占位。pnpm 不展开仓库控制的鉴权环境变量；如需使用环境变量，应在用户级配置中引用。CI 可使用临时用户配置文件。不要提交用户配置或在聊天、日志中输出真实 Key。

```bash
npm ci
npm run setup:browseros
npm run dev
```

`npm ci` 的 postinstall 执行 [HeroUI Pro 安装脚本](../scripts/setup-heroui-pro.mjs)：先检查完整构件，再尝试授权缓存；无可用缓存时需要通过环境变量私下配置 `HEROUI_KEY`，然后运行 `npm run heroui:setup`。脚本不会自动读取项目 `.env` 文件；不要把密钥写进仓库或命令输出。

构建与基础检查：

```bash
npm run typecheck
npm test
npm run build
npm start
npm run package
```

`npm run package` 默认生成 `release/` 下的本机 ad-hoc 签名应用目录。`npm run package:signed` 使用 Developer ID 签名但不公证；`npm run package:release` 需要钥匙串公证凭据，生成签名和公证后的 DMG/ZIP。配置与验证见 [macOS 签名与公证](apple-signing.md)。发布上传、可下载性需要单独验证，目前没有自动更新。

隔离 UI 检查可按改动选择：

```bash
npx tsx tests/homepage-ui.e2e.ts
npx tsx tests/interaction-controls.e2e.ts
npx tsx tests/usage-currency-ui.e2e.ts
npx tsx tests/attention.e2e.ts
npx tsx tests/workbench.e2e.ts
npx tsx tests/onboarding-ui.e2e.ts
npx tsx tests/onboarding.e2e.ts
```

这些测试的前提和输出以脚本为准，Electron 联调需先构建。真实 Codex 集成检查（如 `npm run test:live-agent`）会调用模型；不要把它与模拟 CLI/IPC 的界面检查混在一起，也不要无授权地发真实飞书消息。

前端实现遵循 [DESIGN.md](../DESIGN.md)，工程协作遵循 [AGENTS.md](../AGENTS.md)。第三方依赖许可见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)；仓库自身保持 UNLICENSED，HeroUI Pro 构建需要有效商业授权。

## 能力与验证边界

- 浏览器工作流和本机文件修改已有实现；它们不代表所有网站都兼容。
- 桌面 Computer Use 仍在调研，未实现通用 Mac 应用控制或隔离桌面控制。
- CLI 支持与各自的验收边界见 [本机 CLI 适配](mainstream-cli-support.md)；通用 MCP 服务配置/管理、多 Agent 并行调度、账户/订阅服务尚未实现。
- 已有内部 Neo MCP 工具链不等于任意第三方 MCP 服务都可接入。
- 登录、验证码、支付、外部 OAuth 弹窗和其他敏感流程不得从普通网页验收外推。
- 录制分析尚不提供一键完整 Playwright 测试、PRD 覆盖率报告或后端状态复原。

当前范围与后续研究以 [Computer Use 交接](computer-use-handoff.md) 为准；需要方案、许可和官方来源时再读 [调研报告](computer-use-research.md)。截图必须来自实际应用，Figma 设计稿不能证明功能已经运行。
