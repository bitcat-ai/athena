# 业务领域核对

从实际页面和业务资料建立同一条证据链。不要根据品牌名或视觉风格猜测业务模块。

1. 观察当前网址、页面标题、导航、列表字段和主要动作，识别用户正在处理的业务对象。
2. 用用户配置的知识库检索该对象与业务动作，读取匹配的手册；排除同名或相邻模块的资料。没有资料或页面与手册冲突时明确说明。
3. 向用户回显核对结果：业务领域、实际页面能力、资料中的操作规则及来源。区分页面观察与手册规定。
4. 需要定位源码时，通过 `workbench_repository_resolve` 传入真实网址与已核对的模块。向用户回显返回的应用、仓库、前后端目录、基线与测试分支；没有映射结果就保持未知，不按项目名编造仓库地址。

Skill 只规定核对方法，不提供某个网站的事实。遇到客户材料核对任务，可继续读取 `customer-material-review`。只了解业务时不要开始源码修改；实现、提交按用户当轮要求推进。
